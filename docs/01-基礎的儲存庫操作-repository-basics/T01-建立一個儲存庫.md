# T01：建立一個新的儲存庫

> 所屬階段：[回到第一階段：建立與取得 Repo](README.md) · [課程總覽](../../README.md)

## 任務目標

上一課我們準備好了帳號和工具，這一課就來建立自己的第一個儲存庫吧！老師會陪你認識儲存庫，並練習兩種建立方式：

1. 先在 GitHub 網頁上建立儲存庫，再用 VS Code 複製到電腦。
2. 先在 VS Code 建立本機儲存庫，再發佈到 GitHub。

兩種方式都會得到本機與 GitHub 上的儲存庫；它們只是起點不同。建議兩種都練習一次，使用不同的名稱，才不會混淆。

## 學習重點

- **儲存庫（Repository，簡稱 Repo）**：管理專案檔案與 Git 版本紀錄的地方。每次提交（Commit）可以記錄一個版本，方便日後查看變更。
- **本機與遠端**：本機儲存庫在自己的電腦上；GitHub 上的是遠端儲存庫。兩者不會因為建立或修改檔案就自動保持同步。
- **複製（Clone）**：把遠端儲存庫及其版本紀錄複製到電腦，方便在本機工作。
- **初始化與發佈**：初始化（Initialize）讓資料夾成為本機 Git 儲存庫；發佈（Publish）會在 GitHub 建立新的遠端儲存庫並推送本機提交。
- **公開與私人**：公開（Public）儲存庫可供任何人查看；私人（Private）儲存庫只有獲得存取權的人可以查看。無論選哪一種，都不要放入密碼或權杖。

## 實作練習

### 開始之前

請先完成 [T00：準備 GitHub 帳號與操作環境](T00-註冊Github與設定VSCode.md)，確認 GitHub 和 VS Code 已登入正確帳號，且 `git --version` 能顯示版本號。方法二會建立提交，請先依 T00 的說明設定 Git 使用者名稱與提交電子郵件。

準備一個放練習專案的本機資料夾，並選擇自己有權建立儲存庫的 GitHub 個人帳號。這次會建立兩個不同的練習儲存庫，名稱可以使用下面的範例；如果名稱已被使用，換一個即可。

### 方法一：先在 GitHub 建立，再用 VS Code 複製

#### 在 Web 介面建立一個儲存庫

我們先從網頁開始。建立時加入 README，讓新儲存庫有一個介紹檔案，也方便稍後確認複製結果。

1. 開啟 <a href="https://github.com/" target="_blank" rel="noopener noreferrer">GitHub 首頁</a>並登入。點選右上角的 **+**，再選擇 **New repository**（新增儲存庫）。
2. 確認 **Owner**（擁有者）是自己的帳號，在 **Repository name**（儲存庫名稱）輸入 `practice-web-first`。如果名稱已存在，請改用尚未使用的名稱。
3. 選擇 **Private**（私人）作為這次的練習設定，並開啟 **Add README**（加入 README）選項。README 是用來介紹專案的檔案；其他選項這次可以先維持預設。
4. 確認擁有者、名稱與可見性後，按 **Create repository**（建立儲存庫）。看到儲存庫首頁和 `README.md`，就完成網頁上的建立了。

#### 從 VS Code 中 Clone 一個線上儲存庫

5. 在儲存庫頁面點選 **Code**（程式碼），選擇 **HTTPS**，複製顯示的儲存庫網址。這個網址指向 GitHub 上的遠端儲存庫。
6. 切換到 VS Code，開啟 **Command Palette**（命令面板；Windows／Linux 可按 `Ctrl+Shift+P`，macOS 可按 `Cmd+Shift+P`），輸入並選擇 **Git: Clone**，貼上剛才的網址後按 Enter。
7. 選擇你準備好的本機資料夾作為存放位置。VS Code／Git 會在其中建立儲存庫的子資料夾；不要選擇已有同名專案的位置。Clone 完成後，VS Code 會詢問接下來如何開啟這個儲存庫：
   - **Open**（開啟）：在目前的 VS Code 視窗開啟儲存庫，取代目前視窗中的資料夾或工作區。
   - **Open in New Window**（在新視窗開啟）：保留目前視窗不變，另外開一個 VS Code 視窗開啟儲存庫。若你想同時保留原本的工作，這個選項最合適；初學時老師也建議選這個，原本開啟的專案會保留下來，也比較容易分辨新複製的儲存庫。
   - **Add to Workspace**（加入工作區）：把儲存庫資料夾加入目前的多根目錄工作區，和原有資料夾一起顯示在檔案總管中；不會取代目前的工作區。

   這次練習請選擇 **Open**，直接在目前的 VS Code 視窗開啟剛複製的儲存庫。
8. 在 VS Code 的檔案總管找到 `README.md`，並確認開啟的是剛複製的資料夾。回到 GitHub 網頁核對儲存庫名稱與檔案；也可以在 VS Code 終端機輸入 `git remote -v`，確認 `origin` 指向剛才複製的網址。

如果複製私人儲存庫時要求登入，請依提示完成認證；若仍無法存取，先確認網址、帳號和儲存庫權限。畫面或按鈕名稱可能因版本、語言而略有不同。

### 方法二：先在 VS Code 建立，再發佈到 GitHub

接下來我們從電腦開始。請建立**另一個**全新的空資料夾，不要使用剛才複製的資料夾，也不要放在其他 Git 儲存庫裡。

1. 建立空資料夾 `practice-vscode-first`，在 VS Code 選擇 **File → Open Folder**（檔案 → 開啟資料夾），開啟它。如果出現工作區信任提示，確認是自己建立的資料夾後再繼續。
2. 開啟 **Source Control**（原始檔控制），點選 **Initialize Repository**（初始化儲存庫）。若看不到按鈕，可在命令面板執行 **Git: Initialize Repository**。現在資料夾已是本機 Git 儲存庫，但還沒有上傳到 GitHub。
3. 在 VS Code 檔案總管新增 `README.md`，輸入以下內容並儲存：

   ```markdown
   # VS Code 練習儲存庫

   這是我的 GitHub 練習專案。
   ```

4. 回到 **Source Control**，確認 `README.md` 出現在變更清單。點選檔名檢查內容，再點選檔案旁的 **+**（Stage Changes，暫存變更），將它加入下一次提交。
5. 在提交訊息欄輸入 `新增練習說明`，按 **Commit**（提交）。如果提示設定 Git 使用者名稱或電子郵件，請先回到 T00 完成設定，再試一次。提交成功後，檔案會記錄在**本機**版本歷史中，還沒有上傳。
6. 開啟命令面板，執行 **Publish to GitHub**（發佈至 GitHub）。若要求登入或授權，請確認帳號與授權內容，再依提示繼續。
7. 輸入尚未使用的 GitHub 儲存庫名稱，例如 `practice-vscode-first`，並選擇 **Private**（私人）。發佈前再確認帳號、名稱與可見性；如果畫面要求選擇檔案，請確認只包含你願意上傳的內容，再繼續。
8. 發佈完成後，在 GitHub 網頁開啟新儲存庫，確認 `README.md` 和剛才的提交都在。回到 VS Code 終端機輸入 `git remote -v`，確認 `origin` 指向這個新的 GitHub 儲存庫。

請注意，**Publish to GitHub** 會建立新的遠端儲存庫；它不是把本機資料夾接到方法一已建立的儲存庫。如果名稱衝突或發佈失敗，先檢查帳號、權限與錯誤訊息，不要重複建立或強制推送。

這兩個練習專案彼此獨立。之後在本機修改檔案，還需要提交並推送（Push），GitHub 才會收到更新；後面的課程會再帶你練習。

## 小測驗

在進入下一課之前，來試試看吧！請選出**一個**答案，再展開下方解答確認。

**問題：** 我在 VS Code 建立了本機儲存庫，也完成了第一次提交，但還沒有連接遠端儲存庫。現在想在 GitHub 上建立對應的儲存庫並上傳，開啟命令面板後應該選擇哪個指令？

- A. **Git: Clone**
- B. **Publish to GitHub**
- C. **Git: Pull**
- D. **Git: Initialize Repository**

<details>
<summary>查看答案</summary>

答案是 **B. Publish to GitHub**。它會在 GitHub 建立新的儲存庫，並將本機提交推送上去。Clone 是複製既有儲存庫，Pull 是取得遠端更新，而 Initialize Repository 是在本機初始化儲存庫。

如果儲存庫已經連接到 GitHub，之後要上傳新的提交，通常使用 **Push**，不需要再次建立儲存庫。
