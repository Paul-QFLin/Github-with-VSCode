# T03：發佈 Push 本機儲存庫

> 所屬階段：[回到第一階段：建立與取得 Repo](README.md) · [課程總覽](../../README.md)

## 任務目標

在 T02，我們學會把修改記錄成 Commit。接下來，老師要陪你把本機的提交推送到 GitHub，讓遠端也保存這些版本。

有時 Push（推送）會被拒絕，並提示需要先 Pull（拉取）。別擔心，這通常是因為遠端有本機還沒有的提交。本課會一起了解原因，並在安全的練習情境中試著整合後再推送。

## 學習重點

- **Push 做什麼**：將本機分支上已提交的版本上傳到對應的遠端分支。還沒 Commit 的修改不會隨 Push 上傳。
- **遠端與上游分支**：遠端（Remote）是本機連往另一個儲存庫的設定，常見名稱是 `origin`；上游分支是目前本機分支對應的遠端分支。Push 和 Pull 前，先確認儲存庫、遠端與分支是否正確。
- **為什麼可能要先 Pull**：如果有人在 GitHub 網頁、另一台電腦或其他地方先建立了遠端提交，而本機尚未包含它，直接 Push 可能被拒絕，以避免覆蓋遠端已有的歷史。這時需要先了解並整合遠端變更，再推送。
- **Fetch、Pull 與 Sync**：Fetch（擷取）只取得遠端更新資訊，不整合進目前分支；Pull 會取得並整合遠端提交，可能改變本機檔案；VS Code 的 **Sync Changes**（同步變更）會先 Pull 再 Push。只有確定要同時進行這兩件事時才使用 Sync。
- **Push 與 Publish**：T01 的 **Publish to GitHub** 會建立新的 GitHub 儲存庫；本課的 Push 是把提交上傳到已連接的遠端儲存庫。若分支尚未設定上游，VS Code 可能提示 **Publish Branch**（發佈分支），這和建立新的 GitHub 儲存庫不同。

還記得 T02 的作業比喻嗎？假設雲端作業區已有另一份更新，我們要先取回並整合那份作業，再把包含雙方內容的版本上傳。Pull 不會自動 Push，Push 也不會自動 Pull。

## 實作練習

### 開始之前

請先完成 [T00](T00-註冊Github與設定VSCode.md)、[T01](T01-建立一個儲存庫.md) 和 [T02](T02-提交Commit一個版本.md)。這次使用 T02 在 VS Code 中完成本機 Commit 的那個練習儲存庫，而不是 T02 網頁編輯練習使用的另一個儲存庫。

確認這個儲存庫已連接到你有寫入權限的 GitHub 儲存庫，並在 VS Code 開啟它。若尚未連接遠端，請先參考 T01 發佈儲存庫；若是受保護分支，請遵守該儲存庫的協作規則。

### 1. 確認本機與遠端

1. 在 VS Code 開啟 **Source Control**（原始檔控制），確認選到正確的練習儲存庫與分支。看看 **Changes**（變更）和 **Staged Changes**（已暫存的變更）：若有未完成的修改，請先確認並妥善保留，不要把不相關內容提交或丟棄。
2. 選擇 **Terminal → New Terminal**（終端機 → 新增終端機），確認終端機位於這個儲存庫，依序輸入：

   ```sh
   git remote -v
   git branch -vv
   git --no-pager log -1
   ```

3. 確認 `origin` 的網址是預期的 GitHub 儲存庫；在 `git branch -vv` 中找到有 `*` 的目前分支，確認方括號中的上游分支（例如 `origin/main`）是你要更新的分支。最後確認最新提交訊息是 T02 的本機練習提交。名稱可能和範例不同，以自己的設定為準。
4. 如果看不到預期的遠端或上游分支，先不要推送到不確定的位置。確認已完成 T01 的 Clone 或 Publish；若只是目前分支尚未設定上游，VS Code 可能提供 **Publish Branch**。使用前請核對目標遠端、分支及權限；不確定時，先向老師或儲存庫擁有者確認。

### 2. 推送本機提交

1. 回到 **Source Control**，點選 **... → Push**（更多動作 → 推送），將目前分支的提交上傳。若提示登入或授權，請確認帳號後依畫面操作；介面名稱可能因版本或語言而不同。
2. 等待操作完成。若被拒絕，先閱讀提示，不要使用 Force Push（強制推送）；如果提示遠端有新提交，請先看下面「為什麼需要先 Pull」的說明。其他錯誤則先檢查網路、帳號、權限與分支保護設定。
3. Push 成功後，在 <a href="https://github.com/" target="_blank" rel="noopener noreferrer">GitHub 網頁</a>開啟同一個儲存庫，選擇剛才推送的分支。查看 `README.md` 是否包含 T02 的修改，並在提交紀錄中確認 `新增 Git 練習說明`。若看不到，先核對網址、分支和 Push 結果。

### 3. 為什麼需要先 Pull？

接下來做一個小練習，親眼看看本機和遠端各有新提交時會發生什麼事。請繼續使用**同一個**練習儲存庫及分支，先確認步驟 2 已成功，且沒有尚未提交的修改；這次會分別修改兩個不同檔案，降低發生衝突的機會。

1. 在 GitHub 網頁上確認目前分支與剛才推送的分支相同，依 T02 的網頁編輯方式，在 `README.md` 加一行 `這一行在 GitHub 網頁新增。`，提交訊息輸入 `新增網頁練習說明`。完成後，遠端就有了一個本機還沒有的提交。
2. 暫時不要 Pull。在 VS Code 的同一個練習儲存庫中，新增 `push-practice.md`，寫入 `這是本機的 Push 練習。` 並儲存。檢查並暫存這個檔案，再以 `新增本機 Push 練習` 為訊息 Commit。現在本機和遠端各有一個對方尚未包含的新提交。
3. 在 VS Code 選擇 **... → Push**。由於遠端分支有本機尚未包含的提交，Push 預期會被拒絕。這是保護遠端歷史的提醒，不代表你的本機提交消失了。如果沒有遭到拒絕，請先核對兩邊是否使用同一個儲存庫和分支，以及網頁提交是否已完成；不要重複建立提交。
4. 先確認工作目錄沒有尚未提交的修改，並再次確認 `git branch -vv` 顯示的上游是剛才更新的遠端分支。若有未完成的工作，先妥善保留；Pull 會整合變更，可能改變本機檔案。
5. 在這個練習儲存庫的終端機，依序執行：

   ```sh
   git fetch origin
   git --no-pager log --oneline "HEAD..@{upstream}"
   ```

   第一個指令取得遠端資訊但不整合；第二個指令列出上游分支有、目前本機分支尚未包含的提交。確認清單中有 `新增網頁練習說明`。如果沒有上游或看到非預期的提交，請先停下來確認設定與內容。
6. 確認是預期的遠端更新後，在終端機輸入 `git pull --no-rebase`。這次明確使用合併（Merge）方式整合遠端與本機提交；若 Git 開啟編輯器要求確認合併訊息，儲存並關閉即可。不同專案可能有其他合併或 Rebase 規範，實際協作時請依團隊規則操作。
7. Pull 成功後，確認本機 `README.md` 有網頁新增的那一行，`push-practice.md` 也仍在。接著選擇 **... → Push**；成功後回到 GitHub 的同一分支，確認兩個檔案與提交都存在。

如果 Pull 出現衝突，表示 Git 需要你協助選擇如何整合。請先保留目前內容、閱讀 VS Code 的衝突提示，不要直接丟棄修改或再次 Push；確認解決結果並完成合併後才能繼續。衝突處理會在後面的課程進一步練習。如果本機或遠端內容不如預期，也可以先停下來請老師協助。

## 小測驗

在進入下一課之前，來試試看吧！請選出**一個**答案，再展開下方解答確認。

**問題：** 我在本機完成 Commit 後 Push，Git 提示遠端有我尚未包含的提交，因此拒絕推送。接下來應該怎麼做？

- A. 使用 Force Push 覆蓋遠端。
- B. 確認遠端更新，先妥善保留本機工作並整合遠端提交，再重新 Push。
- C. 刪除本機資料夾，重新建立儲存庫。
- D. 再按一次 Commit，遠端就會自動更新。

<details>
<summary>查看答案</summary>

答案是 **B**。先確認遠端的變更是什麼，並保留尚未提交的工作；Pull 整合完成後，再 Push 分享本機提交。如果整合時發生衝突，需要先解決並完成整合。不要用 Force Push 繞過拒絕，以免覆蓋別人的工作。

</details>
