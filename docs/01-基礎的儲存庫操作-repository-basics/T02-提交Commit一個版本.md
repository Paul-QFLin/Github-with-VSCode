# T02：儲存庫的確認 Commit

> 所屬階段：[回到第一階段：建立與取得 Repo](README.md) · [課程總覽](../../README.md)

## 任務目標

在 T01，我們已經建立了儲存庫，也接觸過一次 Commit。這一課，老師會帶你慢慢認識 Commit（提交）是什麼、為什麼要使用它，並練習在 VS Code 和 GitHub 網頁上記錄修改。

完成後，你會知道如何確認修改、寫一則清楚的提交訊息，並檢查這個版本是否已記錄在本機。

## 學習重點

- **什麼是 Commit**：Commit 是 Git 對專案在某個時間點的已追蹤檔案所記錄的版本，像是一張可以回頭查看的快照。每次提交會包含訊息、作者等資訊，並連結到先前的版本。
- **為什麼需要 Commit**：把適當的修改記錄成版本，可以幫助我們了解改了什麼、何時修改，也讓日後查找或回復變更有依據。清楚的提交訊息，能幫助自己和協作者理解修改目的。
- **儲存、暫存與提交的差別**：儲存（Save）是把編輯內容寫入檔案；暫存（Stage）是選擇下一次提交要包含的修改；提交（Commit）則把已暫存的內容記錄到本機 Git 歷史。
- **Commit 與 Push 的差別**：在 VS Code 的本機儲存庫建立的 Commit 不會自動上傳 GitHub；Push（推送）才會把本機提交上傳到遠端。若直接在 GitHub 網頁編輯並提交，Commit 會記錄在 GitHub 上，與本機操作不同。

### 用作業繳交來想一想

把專案想成你的作業，這幾個動作就比較容易理解了：

| Git 操作 | 作業繳交情境 |
| --- | --- |
| Save（儲存） | 新增或修改一題作業，並把檔案存檔。 |
| Stage（暫存） | 選擇這次要繳交的檔案，不一定每個檔案都交。 |
| Commit（提交） | 把選好的內容記錄成一個版本，就像將選好的作業打包成壓縮檔。 |
| Push（推送） | 把已提交的版本上傳到雲端作業區。 |
| Pull（拉取） | 取得並整合雲端最新的作業版本到本機。 |

這只是幫助理解的比喻：Git 的 Commit 並不是真的建立壓縮檔，而是記錄一個版本；Pull 也可能需要處理本機與遠端的修改衝突。

## 實作練習

### 開始之前

請先完成 [T00](T00-註冊Github與設定VSCode.md) 和 [T01](T01-建立一個儲存庫.md)。這次可以使用 T01 建立或複製的練習儲存庫，並確認 Git 使用者名稱與提交電子郵件已設定。提交的作者資訊會保存在版本歷史中，請使用你願意分享的資料。

## VSCode上的Commit練習 ##

在 VS Code 開啟練習儲存庫後，請先到 **Source Control**（原始檔控制）確認目前的儲存庫與分支。若有尚未完成的修改，或 **Staged Changes**（已暫存的變更）中已有其他內容，先確認並妥善保留；不要把不相關的修改一起提交。以下練習只處理自己的測試資料，不要寫入密碼或權杖。

### 1. 修改並確認檔案

1. 在 VS Code 檔案總管開啟練習儲存庫中的 `README.md`。在原有內容後面加上一行，例如：

   ```text
   我正在練習使用 Git 記錄版本。
   ```

2. 儲存檔案，接著開啟 **Source Control**。你應該會在 **Changes**（變更）中看到 `README.md`，表示 Git 偵測到尚未提交的修改。
3. 點選 `README.md`，看看前後差異，確認增加的內容正是你想記錄的。如果沒有看到變更，請先確認檔案已儲存，並且 VS Code 開啟的是正確的練習儲存庫。

### 2. 暫存並提交

1. 在 **Changes** 中，將滑鼠移到 `README.md` 旁，點選 **+**（**Stage Changes**，暫存變更）。檔案會移到 **Staged Changes**。
2. 點選暫存後的檔案，再檢查一次差異，確認沒有意外加入其他內容。Commit 會記錄暫存時選定的內容；如果之後又修改檔案，記得儲存並重新檢查暫存狀態。
3. 在上方的提交訊息欄(Message的文字框)中輸入 `新增 Git 練習說明`，再按 **Commit**（提交）。***訊息不必很長，但要讓人看得出這次做了什麼***。
4. 如果 Git 提示需要設定使用者名稱或電子郵件，請先回到 T00 的 Git 設定說明完成設定，再重新提交。若出現其他錯誤，先閱讀提示並確認暫存內容；不要急著放棄修改。

提交成功後，這次練習的變更不再出現在待提交清單中。若清單還有其他修改，先確認它們是否是先前保留的工作，不要直接刪除。

### 3. 確認提交紀錄

1. 在 VS Code 選擇 **Terminal → New Terminal**（終端機 → 新增終端機），確認終端機位於剛才的練習儲存庫，再輸入：

   ```sh
   git --no-pager log -1
   ```

2. 看看輸出中是否有剛才的提交訊息 `新增 Git 練習說明`，以及作者和日期。這表示 Git 已經把這次修改記錄在本機歷史中。
3. 回到 GitHub 網頁查看該儲存庫。這次只做了本機 Commit，還沒有 Push；網頁上不會因為這個本機提交而自動更新。我們會在後面的課程練習上傳。

如果看到的不是剛才的訊息，先確認終端機所在的資料夾、目前分支，以及提交是否成功；檔案仍在的話，可以回到前面的步驟再檢查一次。

## GitHub網頁上的Commit練習 ##

除了在 VS Code 操作，我們也可以直接在 GitHub 網頁上修改檔案並建立 Commit。這次請使用自己擁有的**另一個** T01 練習儲存庫，避免和剛才尚未推送的本機提交混在一起。

1. 開啟 <a href="https://github.com/" target="_blank" rel="noopener noreferrer">GitHub 首頁</a>並登入，進入另一個練習儲存庫。確認儲存庫名稱、目前分支和帳號都正確，且你有權修改。
2. 在檔案清單中點選 `README.md`，再點右上方的鉛筆圖示 **Edit this file**（編輯檔案）。
3. 在原有內容後面加上一行，例如 `我正在練習在 GitHub 網頁上提交。`。選擇 **Preview**（預覽）檢查內容，確認沒有意外修改其他文字，也沒有加入密碼或權杖。
4. 點選 **Commit changes...**（提交變更），在 **Commit message**（提交訊息）欄輸入 `新增網頁編輯練習`。確認選擇提交至目前分支後，再按 **Commit changes** 完成提交。
5. 回到檔案或儲存庫頁面，確認新增的文字與提交訊息已出現在 GitHub 上。介面文字可能因版本或語言而略有不同。

如果看不到編輯選項，或無法直接提交到目前分支，請先確認帳號權限及分支是否受保護；有些儲存庫需要透過新分支與 Pull Request（合併請求）提交，不要試圖繞過保護。

小提醒：在GitHub網頁上的 Commit 是直接記錄在 **GitHub 遠端**，不用再 Push 一次；本機副本不會自動更新。之後在本機操作前，先確認並妥善保留尚未提交的修改，再取得並整合遠端更新。若本機與遠端各自有新提交，直接 Push 可能被拒絕；我們會在後面的課程練習 Pull 和處理衝突。

## 小測驗

在進入下一課之前，來試試看吧！請選出**一個**答案，再展開下方解答確認。

**問題：** 我在 VS Code 儲存並暫存修改後按下 **Commit**，這個操作做了什麼？

- A. 把已暫存的內容記錄成一個本機版本。
- B. 自動將修改上傳到 GitHub。
- C. 從 GitHub 複製一個新的儲存庫。
- D. 刪除本機檔案，改用 GitHub 上的版本。

<details>
<summary>查看答案</summary>

答案是 **A**。Commit 會把已暫存的內容記錄到本機 Git 歷史，方便日後查看。它不會自動上傳到 GitHub；要將本機提交分享至遠端，還需要 Push。

</details>
