# T03：推送至遠端 Push 與從遠端拉取 Pull

> 所屬階段：[回到第一階段：建立與取得 Repo](README.md) · [課程總覽](../../README.md)

## 任務目標

在 T02，我們學會了用 Commit 記錄修改。接下來，老師要陪你練習在自己的電腦和 GitHub 之間傳遞版本：用 Push 上傳本機提交，也用 Pull 取得並整合 GitHub 上的更新。

有時 Push 會被拒絕，提示我們先 Pull。別擔心，這一課也會透過小練習，看看為什麼會發生，以及接下來該怎麼做。

## 學習重點

- **本機與遠端**：本機儲存庫在自己的電腦上，遠端儲存庫則可以放在 GitHub 上。兩邊不會因為一方有修改就自動同步。
- **Push（推送）**：把本機已 Commit 的版本上傳到連接的遠端儲存庫。還沒 Commit 的修改不會隨 Push 上傳。
- **Pull（拉取）**：取得遠端的新提交，並將它們整合到本機。Pull 可能改變本機檔案，操作前要先確認並妥善保留未完成的修改。
- **為什麼有時要先 Pull**：如果你在 GitHub 網頁、另一台電腦或與他人協作時先更新了遠端，而本機還沒有那些提交，Push 可能會被拒絕。先了解並整合遠端更新，再推送，就能避免直接覆蓋已有的工作。
- **Push、Pull 和同步**：Push 不會自動 Pull；Pull 也不會自動 Push。VS Code 的 **Sync Changes**（同步變更）則會先 Pull 再 Push，本課先分開操作，比較容易看清楚發生了什麼事。

還記得 T02 的作業比喻嗎？Push 像是把已打包的作業上傳到雲端；Pull 則像是取回雲端更新，並把它整合到自己的作業中。若雲端已有別人更新的內容，就要先了解並整合，再把自己的版本上傳。

## 實作練習

### 開始之前

請先完成 [T00](T00-註冊Github與設定VSCode.md)、[T01](T01-建立一個儲存庫.md) 和 [T02](T02-提交Commit一個版本.md)。這次使用 T02 在 VS Code 中完成本機 Commit 的練習儲存庫；它應已依 T01 複製或發佈到你有權使用的 GitHub 儲存庫。

在 VS Code 開啟這個練習儲存庫，也在 <a href="https://github.com/" target="_blank" rel="noopener noreferrer">GitHub 網頁</a>開啟對應的儲存庫。請確認兩邊是同一個專案，並使用 T01 設定好的連線，不要切換工作位置。若不確定是否連接正確，先停止操作並請老師協助。

這些練習都在自己的測試儲存庫進行。如果是他人的專案或受保護的儲存庫，請先確認權限並遵守協作規則。

### 1. 練習 Push：把本機提交上傳

1. 在 VS Code 開啟 **Source Control**（原始檔控制），確認選到正確的練習儲存庫。檢查 **Changes**（變更）和 **Staged Changes**（已暫存的變更）；若有未完成的修改，請先妥善保留，不要把不相關的內容提交或丟棄。
2. 確認 T02 的本機提交尚未上傳。如果已經上傳，可以在練習儲存庫的 `README.md` 增加一行 `這是我的 Push 練習。`，儲存、檢查並暫存後，以 `新增 Push 練習說明` 為訊息 Commit。請記住這次要上傳的內容與提交訊息。
3. 在 **Source Control** 點選 **... → Push**（更多動作 → 推送）。如果要求登入或授權，請確認帳號後依提示完成。
4. 等待 Push 完成後，回到 GitHub 網頁，查看 `README.md` 和提交紀錄，確認剛才的文字與提交訊息已出現。這表示本機提交已上傳。

如果 Push 被拒絕，先閱讀提示，不要使用 Force Push（強制推送）。若原因是遠端有本機尚未包含的提交，請先參考下方「為什麼需要先 Pull」；若是其他錯誤，請檢查網路、帳號和儲存庫權限。介面名稱可能因版本或語言而不同。

### 2. 練習 Pull：把遠端更新帶回本機

1. 確認步驟 1 已完成，在 VS Code 的 **Source Control** 看看有沒有尚未提交的修改；如果有，先妥善保留或完成提交。本次練習先讓工作目錄保持乾淨，再進行 Pull。
2. 在 GitHub 網頁的同一個練習儲存庫，依 T02 的網頁編輯方式，在 `README.md` 加一行 `這一行在 GitHub 網頁新增。`，以 `新增網頁練習說明` 為訊息提交。
3. 回到 VS Code，先看看本機的 `README.md`：網頁新增的文字不會自動出現。接著在 **Source Control** 選擇 **... → Pull**（更多動作 → 拉取）。
4. Pull 完成後，再打開本機的 `README.md`，確認已看到 `這一行在 GitHub 網頁新增。`。如果沒有看到，請先核對兩邊是否為同一個儲存庫，以及 Pull 是否成功；不要急著重做。

若 VS Code 提示無法 Pull，先閱讀錯誤訊息並確認工作目錄沒有未完成的修改。如果看到與連線或工作位置有關的提示，先停下來請老師協助，不要隨意更改設定。

### 3. 為什麼需要先 Pull？

接下來，我們在同一個練習儲存庫製造一個常見情境：遠端有新提交，本機也有新的提交。請先確認步驟 2 已成功，且沒有未完成的修改。我們會分別修改兩個不同檔案，避免發生衝突的機會(發生衝突的狀況，以後會談)。

1. 在 GitHub 網頁編輯 `README.md`，加上一行 `這是另一個網頁更新。`，以 `新增另一個網頁更新` 為訊息提交。這個新版本此時還沒有在本機。
2. 先不要 Pull。在 VS Code 新增 `push-practice.md`，寫入 `這是本機的 Push 練習。` 並儲存。檢查、暫存後，以 `新增本機 Push 練習` 為訊息 Commit。現在本機和遠端各有一個對方尚未包含的新提交。
3. 在 VS Code 選擇 **... → Push**。由於遠端有本機尚未包含的提交，Push 預期會被拒絕；這是保護遠端已有工作的提醒，本機提交仍然保留。如果沒有被拒絕，先確認網頁提交是否完成、兩邊是否為同一個儲存庫，以及操作是否指向同一個工作位置，不要重複建立提交。
4. 先確認工作目錄沒有尚未提交的修改，再到 GitHub 的提交紀錄查看 `新增另一個網頁更新`，確認這是預期要取回的內容。若有未完成的工作或看到不認識的更新，先停下來確認，不要急著整合。
5. 確認更新無誤後，在 VS Code 選擇 **Terminal → New Terminal**（終端機 → 新增終端機），確認終端機位於這個練習儲存庫，輸入：

   ```sh
   git pull --no-rebase
   ```

   這次我們明確使用合併方式，把遠端更新和本機提交整合在一起；它不會自動 Push。如果 Git 開啟編輯器要求確認合併訊息，請儲存並關閉編輯器。實際協作時，不同專案可能有不同的整合規則，請先依團隊約定操作。
6. Pull 成功後，確認本機 `README.md` 有網頁新增的文字，`push-practice.md` 也仍在。接著在 **Source Control** 選擇 **... → Push**。成功後回到 GitHub 網頁，確認兩個檔案及提交都存在。

如果 Pull 出現衝突，表示 Git 需要你協助整合內容。請先保留目前的工作、閱讀 VS Code 的提示，不要直接丟棄修改、強制推送或再次 Push；確認並完成整合後才能繼續。衝突處理會在後面的課程進一步練習，也可以先請老師協助。

## 小測驗

在進入下一課之前，來試試看吧！請選出**一個**答案，再展開下方解答確認。

**問題：** 我在本機完成 Commit 後 Push，Git 提示遠端有我尚未包含的提交，因此拒絕推送。接下來應該怎麼做？

- A. 使用 Force Push 覆蓋遠端。
- B. 確認遠端更新，先妥善保留本機工作並整合遠端提交，再重新 Push。
- C. 刪除本機資料夾，重新建立儲存庫。
- D. 再按一次 Commit，遠端就會自動更新。

<details>
<summary>查看答案</summary>

答案是 **B**。先確認遠端的變更是什麼，並保留尚未提交的工作；Pull 整合完成後，再 Push 分享本機提交。如果整合時發生衝突，需要先解決並完成整合。不要用 Force Push 繞過拒絕，以免覆蓋別人的工作。

</details>

## 完成檢查

- [ ] 我已將本機提交 Push 到 GitHub，並在網頁上找到這次修改。
- [ ] 我已將 GitHub 網頁上的更新 Pull 回本機，並在 VS Code 確認內容。
- [ ] 我能解釋遠端有新提交時為什麼可能需要先 Pull，也知道 Pull 可能改變本機檔案。
- [ ] 我已練習整合本機與遠端的提交，再 Push，並確認兩邊的練習內容。
- [ ] 我知道 Push 被拒絕時不應直接強制推送；遇到衝突時要先完成整合。
