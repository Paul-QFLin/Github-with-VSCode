# T06：回復與放棄修改

> 所屬階段：[回到第二階段：版本檢視與協作](README.md) · [課程總覽](../../README.md)

## 任務目標

在 T05，我們練習了查看檔案差異與 Commit History。這一課，老師會帶你分辨尚未提交的修改和已提交的版本，並依照狀態選擇安全的處理方式：

- 尚未提交而且確定不需要的修改，可以在 VS Code 放棄。
- 已經 Commit 的內容，不要直接刪除或改寫歷史；使用 `git revert` 建立一筆新的 Commit，記錄反向修改。

練習前會先確認檔案和差異，避免把仍需要的工作一起放棄。請只在自己的測試儲存庫操作。
- **Why or Why Not:**依照修改是否已提交選擇放棄或Revert，能撤回不需要的內容，同時保留已提交的歷史紀錄，降低誤刪與改寫歷史的風險。

## 學習重點

- **尚未提交的修改**：還沒有成為 Commit 的內容，可能位於 **Changes**（未暫存）或 **Staged Changes**（已暫存）。
- **取消暫存不等於放棄修改**：Unstage（取消暫存）會把內容移出 **Staged Changes**，但保留檔案修改；Discard Changes（放棄變更）則會丟棄尚未提交的修改，可能無法復原。
- **已提交的修改**：已經記錄在 Commit History 中，即使尚未 Push，也已成為本機版本歷史的一部分。
- **Revert（反向提交）**：建立新的 Commit 來反轉某筆已提交的修改；原本的 Commit 仍留在歷史紀錄中。這通常比改寫已分享的歷史安全。
- **操作前先確認**：檢查目前儲存庫、分支、檔案差異與 Commit，確認目標是自己的練習內容，再進行放棄或回復。

## 實作練習

### 開始之前

請先完成第一階段 [T00](../01-基礎的儲存庫操作-repository-basics/T00-註冊Github與設定VSCode.md)～[T03](../01-基礎的儲存庫操作-repository-basics/T03-推送至遠端Push與從遠端拉取Pull.md)，以及本階段的 [T04：衝突發生的處理](T04-衝突發生的處理.md) 和 [T05：查看變更與版本紀錄](T05-查看變更與版本紀錄.md)。

在 VS Code 開啟自己有權操作的測試儲存庫，確認資料夾與分支正確。開始前，先查看 **Source Control**（原始檔控制）的 **Changes**、**Staged Changes**，並確認沒有其他尚未完成的修改或尚未推送的 Commit。若工作區不乾淨或你不確定變更屬於誰，先妥善保留並請老師協助，不要直接放棄或推送。

這次會建立專用練習檔 `recovery-practice.md`。請不要在正式專案、共用專案或含有重要工作的儲存庫練習。

### 1. 建立並推送練習檔案

1. 在 VS Code 檔案總管新增 `recovery-practice.md`，輸入並儲存以下內容：

   ```text
   這是回復與放棄修改的練習檔案。
   ```

2. 在 **Source Control** 確認 **Changes** 只有這個練習檔案。將它 Stage（暫存），確認出現在 **Staged Changes**，再以 `新增回復練習檔案` 為訊息 Commit。
3. 依 T03 的方式 Push，並在 GitHub 網頁確認檔案已出現。這會建立共同的練習起點，後續只處理這個檔案。
4. 如果 Commit 或 Push 被拒絕，先看清楚錯誤訊息並確認工作位置和遠端；不要使用 Force Push（強制推送）。

### 2. 了解取消暫存與放棄尚未提交的修改

1. 在 VS Code 開啟 `recovery-practice.md`，將原文改成：

   ```text
   這是尚未提交、稍後要放棄的修改。
   ```

   儲存後，在 **Changes** 點選檔案查看差異，確認這是剛才自己做的練習修改。
2. 在 **Changes** 將檔案 Stage。它會移到 **Staged Changes**；點選檔案再次確認暫存的內容。
3. 在 **Staged Changes** 對該檔案選擇 **Unstage Changes**（取消暫存；可能顯示為 **-** 圖示或出現在右鍵選單）。確認檔案回到 **Changes**，再點選檔案檢查：修改還在，並沒有被放棄。
4. 現在確認這個測試修改確定不需要保留。在 **Changes** 對 `recovery-practice.md` 開啟檔案的更多動作或右鍵選單，選擇 **Discard Changes**（放棄變更），並在確認視窗再次核對檔名與操作內容後才繼續。
5. 回到檔案內容，確認它恢復成第一步之前的文字；再查看 **Source Control**，確認這次練習的未提交修改已不在 **Changes** 或 **Staged Changes**。

**請特別留意：** Discard Changes 會丟棄該檔案尚未提交的修改，可能無法取回。若檔案內有任何需要保留的內容，請不要選擇它；先備份或請老師協助。取消暫存只會改變暫存狀態，不會代替你保存備份。

### 3. 對已提交的修改建立反向 Commit

這次我們不放棄修改，而是先正常提交並推送，再用 `git revert` 建立新的反向提交，保留原始 Commit 作為歷史紀錄。

1. 在 `recovery-practice.md` 原文後面新增並儲存一行：

   ```text
   這一行已經提交，接著會用 Revert 回復。
   ```

2. 在 **Source Control** 查看差異，只 Stage 這次新增的練習內容。確認 **Staged Changes** 中只有預期的修改後，以 `新增已提交的回復練習` 為訊息 Commit。
3. 記下這筆 Commit 的識別碼。在 VS Code 終端機確認目前位置是測試儲存庫，輸入：

   ```sh
   git --no-pager log --oneline
   ```

4. 在最上方找到 `新增已提交的回復練習`，複製該筆紀錄開頭的短識別碼。再次確認它是剛才自己的提交，且目前沒有其他未完成的修改或不相關的尚未推送提交。
5. 依 T03 Push 這筆練習提交。回到 GitHub 確認 `recovery-practice.md` 上有新增的文字，以及提交紀錄中有 `新增已提交的回復練習`。
6. 在終端機執行以下指令，將 `<提交編號>` 換成步驟 4 記下的短識別碼：

   ```sh
   git revert --no-edit <提交編號>
   ```

   這會建立一筆新的 Commit，反轉指定 Commit 的修改；`--no-edit` 使用 Git 預設的 Revert 提交訊息。執行前再確認短識別碼指向本次練習提交。不要將尖括號或佔位文字原樣輸入。
7. 指令完成後，在 VS Code 檢查 `recovery-practice.md`：新增的那一行應已被移除，原有練習文字仍在。再輸入：

   ```sh
   git --no-pager log --oneline
   ```

   確認紀錄中同時保留原本的 `新增已提交的回復練習` Commit，以及一筆新的 `Revert "新增已提交的回復練習"` Commit。
8. 確認這次新產生的 Revert Commit 是唯一需要上傳的變更後，Push 到 GitHub。回到網頁確認原本的提交仍在歷史紀錄中、最新的 Revert 提交也已出現，而且檔案內容已回復。

如果 Git 顯示錯誤或 Revert 產生衝突，先停止操作並保留目前狀態，閱讀錯誤訊息；不要重複執行 Revert、使用 `reset --hard` 或強制推送。不確定如何處理時，請老師協助。

## 小測驗

在進入下一課之前，來試試看吧！請選出**一個**答案，再展開下方解答確認。

**問題：** 一筆 Commit 已經 Push 到 GitHub，現在發現內容不應保留。想讓歷史清楚保留原提交與修正過程，應該怎麼做？

- A. 在 GitHub 刪除原始 Commit，讓紀錄消失。
- B. 使用 `git reset --hard` 回到前一版，再強制推送覆蓋 GitHub。
- C. 使用 `git revert` 建立一筆反轉修改的新 Commit，再 Push。
- D. 將檔案移出資料夾，GitHub 就會自動撤銷原提交。

<details>
<summary>查看答案</summary>

答案是 **C**。`git revert` 會建立新的 Commit 來反轉指定修改，因此原始提交仍保留在歷史紀錄中。若該提交已經分享給 GitHub 或其他協作者，這通常比改寫既有歷史安全。

</details>
