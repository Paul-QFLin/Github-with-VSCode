# T07：建立、切換與合併分支

> 所屬階段：[回到第二階段：版本檢視與協作](README.md) · [課程總覽](../../README.md)

## 任務目標

前面幾課，我們都直接在目前的分支上修改。這一課，老師會帶你認識 Git branch（分支）：先從 `main` 建立一個新的工作分支，在新分支修改並 Commit，再切回 `main` 檢查差異，最後把完成的工作合併回 `main`。

分支就像從目前版本另開一條工作線。你可以先在自己的分支完成修改，不影響 `main` 上原本的內容；準備好後再整合。這次會在 VS Code 操作，練習只使用自己的測試儲存庫。

## 學習重點

- **分支（Branch）**：指向一系列 Commit 的工作線。建立分支時會以目前所在版本作為起點。
- **建立分支與切換分支**：建立分支會新增一條工作線；切換分支則會讓 VS Code 顯示並操作該分支的檔案與提交。
- **在分支上 Commit**：Commit 會記錄在目前所在的分支。開始修改前先確認 VS Code 左下角顯示的分支名稱。
- **合併（Merge）**：將指定分支的提交與修改整合到目前分支。合併前要先切換到要接收修改的分支。
- **分支合併與衝突**：若 Git 無法自動決定如何整合修改，就會發生衝突；依照 [T04：衝突發生的處理](T04-衝突發生的處理.md) 檢查、解決並完成合併。
- **本機與 GitHub**：新建的本機分支不會自動出現在 GitHub。這一課先練習本機分支與合併；將分支上傳及透過 Pull Request 協作會在 T08 練習。

## 實作練習

### 開始之前

請先完成第一階段 [T00](../01-基礎的儲存庫操作-repository-basics/T00-註冊Github與設定VSCode.md)～[T03](../01-基礎的儲存庫操作-repository-basics/T03-推送至遠端Push與從遠端拉取Pull.md)，以及本階段 [T04](T04-衝突發生的處理.md)～[T06](T06-回復與放棄修改.md)。

使用自己有權限操作的測試儲存庫。在 VS Code 開啟正確的資料夾，並依 T03 確認本機與 GitHub 已同步。檢查 **Source Control**（原始檔控制）的 **Changes** 和 **Staged Changes**；若有未完成的修改或尚未推送的提交，先妥善保留，不要把不相關的工作一起提交或推送。

### 1. 建立共同的練習起點

1. 在 VS Code 檔案總管新增 `branch-practice.md`，輸入以下內容並儲存：

   ```text
   這是分支練習的共同起點。
   ```

2. 在 **Source Control** 檢查變更，將 `branch-practice.md` 暫存，以 `新增分支練習檔案` 為訊息 Commit。
3. 確認目前所在分支是 `main`，再依 T03 的方式 Push。到 GitHub 確認 `branch-practice.md` 已出現在測試儲存庫。
4. 如果 Push 被拒絕，先讀取提示並確認遠端更新；不要使用 Force Push（強制推送）。

### 2. 建立並切換到工作分支

1. 在 VS Code 左下角點選目前的分支名稱，開啟分支選單，選擇 **Create New Branch...**（建立新分支）。若你的 VS Code 版本顯示的文字稍有不同，請尋找建立分支的選項。
2. 輸入分支名稱 `feature/add-introduction` 並按 Enter。若畫面詢問分支起點，選擇目前的 `main`。
3. 建立完成後，查看 VS Code 左下角的分支名稱，確認目前已切換到 `feature/add-introduction`。
4. 再次確認分支名稱後，開啟 `branch-practice.md`，在共同起點後新增一行：

   ```text
   這一行是在 feature/add-introduction 分支完成的。
   ```

5. 儲存檔案，在 **Source Control** 檢查差異，確認只有剛才新增的內容；將修改暫存，以 `在功能分支新增介紹` 為訊息 Commit。

如果看不到新分支或切錯分支，先不要修改檔案；重新從左下角分支選單確認目前分支。

### 3. 切回 main 並確認分支彼此獨立

1. 點選 VS Code 左下角的分支名稱，從分支清單選擇 `main`。
2. 開啟 `branch-practice.md`，確認它目前仍只有共同起點，沒有 `feature/add-introduction` 上新增的那一行。這表示分支上的修改尚未合併到 `main`。
3. 若 VS Code 提示有未提交修改，先停止並檢查來源，不要選擇丟棄修改。

### 4. 將工作分支合併回 main

合併會把工作分支的變更整合到**目前所在的分支**。所以這一步要先確認左下角顯示 `main`，再合併 `feature/add-introduction`。

1. 確認目前分支是 `main`，且 **Changes** 與 **Staged Changes** 沒有未完成的變更。
2. 開啟命令面板（Windows／Linux：`Ctrl+Shift+P`；macOS：`Cmd+Shift+P`），輸入並選擇 **Git: Merge Branch...**（合併分支）。也可以在 **Source Control** 的 **...** 選單中尋找分支合併選項。
3. 在清單選擇 `feature/add-introduction` 作為要合併進目前 `main` 的分支。若 VS Code 顯示不同分支名稱，先取消並重新確認目前分支和要合併的來源，不要猜選。
4. 合併完成後，開啟 `branch-practice.md`，確認共同起點和功能分支新增的文字都存在。查看 **Source Control** 及提交紀錄，確認 Git 已完成整合。若此次合併採用 Fast-forward（快轉），不一定會多出一筆獨立的合併 Commit；功能分支上的 Commit 仍已納入 `main`。
5. 確認合併結果正確後，選擇 **... → Push**，將 `main` 上已整合的版本推送到 GitHub。回到網頁確認檔案包含新增文字。

### 如果合併時發生衝突

如果 Git 暫停合併並顯示衝突，先不要重複合併或直接放棄修改。依照 [T04：衝突發生的處理](T04-衝突發生的處理.md) 比較衝突兩側、整理正確內容、儲存並暫存，確認所有衝突都已處理後再完成合併。若 VS Code 顯示不熟悉的狀態，先停止並請老師協助。

## 小測驗

在進入下一課之前，來試試看吧！請選出**一個**答案，再展開下方解答確認。

**問題：** 我想把 `feature/add-introduction` 的修改合併到 `main`，在 VS Code 應該先做什麼？

- A. 留在功能分支，選擇合併 `main`，這樣修改就會進入 `main`。
- B. 先切換到 `main`，再選擇合併 `feature/add-introduction`。
- C. 直接 Push 功能分支，不需要切換或合併。
- D. 刪除 `main`，讓功能分支自動成為主要分支。

答案是 **B**。合併會把指定分支的工作整合到目前所在的分支，因此要先切換到接收修改的 `main`，再合併 `feature/add-introduction`。
