# T05：查看變更與版本紀錄

> 所屬階段：[回到第二階段：版本檢視與協作](README.md) · [課程總覽](../../README.md)

## 任務目標

在前面的課程中，我們練習了儲存、暫存、Commit、Push 和衝突處理。這一課，老師會帶你用 VS Code 比較檔案修改前後的差異，確認哪些內容尚未暫存、哪些內容已準備好納入下一次 Commit，並查看本機與 GitHub 上的 Commit History（提交紀錄）。

學會查看差異與紀錄，就能在提交前確認自己要交出的內容，也能在事後找回「改了什麼、由誰提交、何時提交」等線索。
- **Why or Why Not:**查看差異與版本紀錄能在提交前核對修改內容，並在事後追查變更的內容、時間與來源。

## 學習重點

- **差異（Diff）**：比較檔案的兩個版本，找出新增、刪除或修改的內容。通常以 `+` 標示新增行、以 `-` 標示刪除行。
- **尚未暫存與已暫存的差異**：VS Code 的 **Changes**（變更）顯示尚未暫存的內容；**Staged Changes**（已暫存的變更）顯示目前準備放進下一次 Commit 的內容。
- **Commit History**：提交紀錄會列出已完成的 Commit。每筆紀錄包含提交訊息及相關資訊；較新的提交通常排在前面。
- **本機與 GitHub 的紀錄**：本機 Commit 會先記錄在本機儲存庫。要讓 GitHub 上也看得到，還需要 Push；網頁編輯並提交的內容則直接記錄在 GitHub 上。

## 實作練習

### 開始之前

請先完成第一階段 [T00](../01-基礎的儲存庫操作-repository-basics/T00-註冊Github與設定VSCode.md)～[T03](../01-基礎的儲存庫操作-repository-basics/T03-推送至遠端Push與從遠端拉取Pull.md)，以及本階段 [T04：衝突發生的處理](T04-衝突發生的處理.md)。使用自己有權限操作的測試儲存庫，並在 VS Code 開啟正確的資料夾與儲存庫。

開始前先查看 **Source Control**（原始檔控制）的 **Changes** 和 **Staged Changes**，並依 T03 確認測試儲存庫已與 GitHub 同步。如果有先前留下的修改或尚未推送的 Commit，請先辨認並妥善保留；不要把不相關的檔案或提交一起推送，也不要為了讓清單變空而丟棄修改。這次練習會修改已追蹤的 `README.md`，不需要建立新的檔案。

### 1. 查看尚未暫存的差異

1. 在 VS Code 的檔案總管開啟測試儲存庫中的 `README.md`，在原有內容後面加上一行：

   ```text
   我正在練習查看尚未暫存的差異。
   ```

2. 儲存檔案，開啟 **Source Control**。在 **Changes** 中找到 `README.md`，點選它以開啟差異檢視。
3. 確認差異檢視中新增的文字與剛才輸入的內容相同。綠色或帶有 `+` 的行通常表示新增；若原內容被修改或刪除，請仔細確認顯示的變化。
4. 如果看不到 `README.md`，請先確認檔案已儲存、檔案原本已受 Git 追蹤，並且 VS Code 開啟的是正確的儲存庫。

差異檢視是用來檢查內容的地方。要修改檔案，請回到一般編輯器；檢查前後不要直接接受或丟棄任何變更。

### 2. 暫存後查看準備提交的差異

1. 在 **Changes** 清單將滑鼠移到 `README.md` 旁，點選 **+**（**Stage Changes**，暫存變更）。檔案會移到 **Staged Changes**。
2. 點選 **Staged Changes** 中的 `README.md`，再次查看差異。確認這次準備提交的新增文字正確，而且沒有其他不想提交的內容。
3. 暫存只會選定下一次 Commit 要包含的內容，不會建立 Commit，也不會上傳 GitHub。

接著我們再做一個小修改，讓你同時比較兩種清單：

4. 回到一般編輯器，在 `README.md` 再新增一行：

   ```text
   這一行目前尚未暫存。
   ```

   儲存後回到 **Source Control**。同一個 `README.md` 現在可能同時出現在 **Changes** 與 **Staged Changes**。

5. 點選 **Changes** 中的 `README.md`，確認這裡顯示的是剛新增、尚未暫存的第二行；再點選 **Staged Changes** 中的 `README.md`，確認這裡顯示的是第一行、目前準備提交的內容。
6. 在 **Changes** 中將 `README.md` 暫存。現在兩行都應納入 **Staged Changes**。點選該檔案，確認兩行都是你預期要提交的內容。

如果兩個清單的內容與預期不同，先停下來逐一查看；不要按 **Commit**，也不要使用 **Discard Changes**（放棄修改）。

### 3. 建立 Commit 並查看本機紀錄

1. 確認 **Staged Changes** 中只有這次練習預期提交的內容。在提交訊息欄輸入 `新增差異檢視練習內容`，再按 **Commit**。
2. 提交後，Source Control 中這次練習的變更會從待提交清單移除。若仍有其他檔案或修改，先確認它們是否是先前保留的工作，不要直接丟棄。
3. 在 VS Code 選擇 **Terminal → New Terminal**（終端機 → 新增終端機），確認終端機位於這個測試儲存庫，再輸入：

   ```sh
   git --no-pager log --oneline
   ```

4. 查看輸出最上方的提交，確認能找到 `新增差異檢視練習內容`。這個指令會以精簡格式列出本機提交紀錄，並避免開啟分頁器；較新的紀錄會在清單上方。

如果找不到訊息，先確認終端機目前所在的資料夾和分支，再回到 Source Control 查看 Commit 是否完成。不要因為一時找不到就重複建立提交。

### 4. 推送後查看 GitHub 上的紀錄

本機剛建立的 Commit 還不會自動出現在 GitHub。接下來依照已學過的 T03 Push 流程，把這次測試提交上傳，方便我們在 GitHub 網頁上比對紀錄。

1. 在 VS Code 的 **Source Control** 確認只有這次練習的 Commit 尚未推送，再選擇 **... → Push**（更多動作 → 推送）。若還有其他未推送的 Commit，先檢查它們是否都應上傳；如果不確定，先停止並請老師協助。
2. 推送完成後，開啟 <a href="https://github.com/" target="_blank" rel="noopener noreferrer">GitHub</a>，進入同一個測試儲存庫。確認網頁上的 `README.md` 已包含本次新增的兩行。
3. 在儲存庫的 **Code**（程式碼）頁面找到提交紀錄入口；它通常會顯示最近提交或提交數量，位置可能因介面版本而稍有不同。點開紀錄清單，確認最上方看得到 `新增差異檢視練習內容`。
4. 點選該筆提交，查看提交訊息、作者、時間，以及這次修改的檔案和差異。確認顯示的內容與 VS Code 中剛才檢查的兩行相同。

如果 GitHub 上看不到剛才的提交，先確認 Push 是否成功、GitHub 網頁是否開啟正確的儲存庫，以及目前檢視的分支是否相同。網頁記錄不會顯示尚未推送的本機 Commit。

## 小測驗

在進入下一課之前，來試試看吧！請選出**一個**答案，再展開下方解答確認。

**問題：** VS Code 的 `README.md` 同時出現在 **Changes** 和 **Staged Changes**，這代表什麼？

- A. 同一個檔案出現重複錯誤，應立即刪掉其中一份。
- B. **Staged Changes** 中有已暫存、準備提交的修改；**Changes** 中還有另一部分尚未暫存的修改。
- C. 這個檔案已經自動提交並上傳到 GitHub。
- D. VS Code 已經替我們完成 Commit，不必再檢查。

<details>
<summary>查看答案</summary>

答案是 **B**。同一個檔案可以同時有已暫存和未暫存的修改。Commit 只會記錄已暫存的內容；操作前要分別查看兩邊，確認準備提交的內容正確。Commit 後若要讓 GitHub 也收到，還需要 Push。

</details>
