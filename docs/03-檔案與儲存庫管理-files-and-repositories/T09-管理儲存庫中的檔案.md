# T09：管理儲存庫中的檔案

> 所屬階段：[回到第三階段：檔案與 Repo 管理](README.md) · [課程總覽](../../README.md)

## 任務目標

在前面的課程，我們練習了修改檔案並 Commit。這一課，老師會帶你在 VS Code 新增、刪除和重新命名檔案，也會看看 Git 如何顯示這些變更。最後，我們會練習選擇這次要提交的檔案，不把其他修改一起放進 Commit。

檔案在電腦上新增或刪除，不代表 Git 已經把變更記錄下來。提交前先到 **Source Control**（原始檔控制）檢查變更，再選擇要暫存的內容。刪除或重新命名前，記得確認檔名和檔案內容；這次請使用自己的測試儲存庫練習。
- **Why or Why Not**: 正確管理檔案並檢查、選擇要提交的變更，能讓版本紀錄反映預期的專案內容，避免誤刪或混入不相關修改。

## 學習重點

- **未追蹤（Untracked）**：新建的檔案尚未被 Git 記錄，通常會出現在 **Changes**（變更）中。
- **已追蹤（Tracked）**：已經由 Git 記錄過的檔案。修改、刪除或重新命名後，Git 會在變更清單中顯示待處理的變更。
- **暫存（Stage）**：選擇下一次 Commit 要包含的檔案變更。只有暫存的內容會納入這次 Commit。
- **重新命名檔案**：重新命名後，Git 可能顯示為重新命名，也可能分別顯示舊檔案刪除和新檔案新增；請確認舊名稱已消失、新檔案存在且內容正確。
- **刪除檔案**：刪除已追蹤的檔案會成為待提交的變更。操作前先確認檔名及內容，避免刪到需要保留的檔案。

## 實作練習

### 開始之前

請先完成第一階段 [T00](../01-基礎的儲存庫操作-repository-basics/T00-註冊Github與設定VSCode.md)～[T03](../01-基礎的儲存庫操作-repository-basics/T03-推送至遠端Push與從遠端拉取Pull.md)，以及第二階段 [T04](../02-版本控制-version-control/T04-衝突發生的處理.md)～[T08](../02-版本控制-version-control/T08-使用Pull-Request協作.md)。

在 VS Code 開啟自己有權限操作的測試儲存庫，確認資料夾和分支正確，並依 T03 確認本機與 GitHub 已同步。打開 **Source Control** 檢查 **Changes** 和 **Staged Changes**；若有未完成的修改，先妥善保留，不要把不相關的工作一起提交或丟棄。

本次練習會使用 `file-practice.md`、`rename-before.md`、`delete-practice.md` 和 `extra-practice.md`。如果測試儲存庫中已有同名檔案，請改用不同名稱，避免覆寫原有內容。請勿在正式專案或含有重要工作的儲存庫中練習。

### 1. 新增並提交練習檔案

1. 在 VS Code 檔案總管新增 `file-practice.md`、`rename-before.md` 和 `delete-practice.md`，分別輸入以下內容並儲存：

   ```text
   這是檔案管理的修改練習。
   ```

   ```text
   這是重新命名練習的起始檔案。
   ```

   ```text
   這是刪除練習檔案，稍後會在測試儲存庫中刪除。
   ```

2. 打開 **Source Control**，確認三個新檔案都出現在 **Changes**。它們是新檔案，尚未被 Git 記錄。
3. 暫存這三個檔案，確認它們都出現在 **Staged Changes**，再以 `新增檔案管理練習` 為訊息 Commit。
4. Commit 完成後，確認這些檔案已不在變更清單中。它們現在已記錄在本機 Git 歷史中。

如果暫存清單中出現其他檔案，先不要 Commit；逐一檢查內容，取消不屬於本次練習的暫存。

### 2. 修改、新增、重新命名與刪除檔案

1. 開啟已追蹤的 `file-practice.md`，在原文後新增一行並儲存：

   ```text
   這一行是已追蹤檔案的修改。
   ```

   在 **Changes** 中點選檔案查看差異，確認只有剛才新增的內容。
2. 在檔案總管新增 `extra-practice.md`，輸入以下內容並儲存：

   ```text
   這是尚未被 Git 記錄的新檔案。
   ```

   回到 **Source Control**，確認這個新檔案也出現在 **Changes**。它尚未被追蹤，和剛才已追蹤檔案的修改不同。
3. 在 VS Code 檔案總管對 `rename-before.md` 按右鍵，選擇 **Rename**（重新命名），改成 `rename-after.md`。確認檔案總管顯示新名稱，再到 **Source Control** 查看變更。Git 可能將它顯示為重新命名，也可能分成舊檔案刪除與新檔案新增。
4. 在檔案總管確認 `delete-practice.md` 是剛才建立的練習檔，且內容不需要保留。對它按右鍵選擇 **Delete**（刪除），並在確認視窗再次核對檔名後才繼續。
5. 回到 **Source Control**，檢查目前的變更：`file-practice.md` 有修改、`extra-practice.md` 是新檔案、`rename-before.md` 已重新命名，`delete-practice.md` 已刪除。畫面顯示方式可能因 VS Code 版本而不同；若有不確定的變更，先停下來確認。

### 3. 選擇要提交的變更

1. 在 **Changes** 中只暫存 `extra-practice.md`、`rename-after.md` 和 `delete-practice.md` 的變更。若重新命名分別顯示成新增與刪除，請確認兩項都是剛才的重新命名，再一起暫存。
2. 檢查 **Staged Changes**：確認只有新增、重新命名和刪除的練習檔案；`file-practice.md` 的修改應該仍留在 **Changes**。
3. 確認暫存內容正確後，以 `管理練習檔案` 為訊息 Commit。Commit 完成後，檔案總管應有 `extra-practice.md` 和 `rename-after.md`，不再有 `rename-before.md` 和 `delete-practice.md`；`file-practice.md` 的修改仍留在 **Changes**。
4. 現在只暫存 `file-practice.md`，查看差異並確認內容正確，再以 `修改檔案管理練習說明` 為訊息 Commit。
5. 回到 **Source Control** 確認本次練習沒有未提交的變更。你已經將不同檔案變更分成兩筆 Commit；若要分享至 GitHub，依 T03 Push，並在 GitHub 確認檔案結果。

如果不小心暫存了不想提交的檔案，在 **Staged Changes** 對它選擇 **Unstage Changes**（取消暫存），確認它仍保留在 **Changes**，再重新選擇。若不確定是否要保留某個修改，不要選擇 **Discard Changes**（放棄變更）；先查看差異或請老師協助。

### 終端機補充

在 VS Code 選擇 **Terminal → New Terminal**（終端機 → 新增終端機），確認終端機位於測試儲存庫後，可以用以下指令查看檔案狀態：

```sh
git status
```

新增及暫存指定檔案可使用 `git add <檔案>`；刪除已追蹤的檔案並暫存刪除可使用 `git rm <檔案>`；重新命名並暫存變更可使用 `git mv <原檔案> <新檔案>`。使用前先確認檔名和目標，Commit 前再用 `git status` 檢查暫存內容。

## 小測驗

在進入下一課之前，來試試看吧！請選出**一個**答案，再展開下方解答確認。

**問題：** 我修改了一個已追蹤檔案，也新增了一個未追蹤檔案，但這次只想提交新增的檔案，應該怎麼做？

- A. 直接按 Commit，Git 會自動挑選最新的檔案。
- B. 只暫存新增檔案，確認它出現在 **Staged Changes**，再 Commit。
- C. 刪除已追蹤檔案，修改就不會被提交。
- D. 使用 `git add .`，不必檢查有哪些變更。

<details>
<summary>查看答案</summary>

答案是 **B**。Stage 是選擇下一次 Commit 要包含的變更。只暫存新增檔案並檢查 **Staged Changes**，就能讓其他修改留在 **Changes**，不被這次提交包含。

</details>

## 完成檢查

- [ ] 我已新增、刪除及重新命名檔案，並在 Source Control 檢查 Git 偵測到的變更。
- [ ] 我知道重新命名可能顯示為新增與刪除，也知道要確認新舊檔案及內容。
- [ ] 我已選擇性暫存變更，確認 **Staged Changes** 只有這次要提交的內容。
- [ ] 我已將不同的檔案變更分別 Commit，且沒有把未選取的修改一起提交。
- [ ] 我知道刪除或放棄修改前要先確認檔案和內容。

都確認好了嗎？很棒！如果有不確定的檔案狀態，先查看 Source Control 的差異與暫存清單，不用急著 Commit。準備好後，可以繼續[第三階段 T10：忽略不需要追蹤的檔案](README.md)。
