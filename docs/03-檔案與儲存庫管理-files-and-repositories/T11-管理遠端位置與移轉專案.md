# T11：管理遠端位置與移轉專案

> 所屬階段：[回到第三階段：檔案與 Repo 管理](README.md) · [課程總覽](../../README.md)

## 任務目標

在 T03，我們練習了把本機提交 Push 到 GitHub，也從 GitHub Pull 更新到本機。這一課，老師會帶你查看 Git 儲存庫設定的遠端位置，練習新增、修改和移除遠端連線，並分清楚「修改本機遠端網址」和「在 GitHub 移轉儲存庫」是兩件不同的事。

遠端設定會影響 Push 和 Pull 的目標。操作前先確認目前開啟的資料夾、遠端名稱和網址；練習只使用自己的測試儲存庫。尤其不要在不確定時 Push，避免把內容傳到錯誤的儲存庫。

## 學習重點

- **遠端（Remote）**：本機 Git 儲存庫記住的遠端儲存庫位置。`origin` 是常見的遠端名稱，但名稱可以不同。
- **查看遠端**：使用 `git remote -v` 查看遠端名稱及網址，通常會看到 Fetch（取得）和 Push（推送）兩種用途。
- **修改遠端網址**：更新本機設定中遠端名稱所指向的網址；這不會搬移或更改 GitHub 上的儲存庫。
- **新增或移除遠端**：本機可以設定多個遠端，也可以移除某個遠端設定。移除設定不會刪除 GitHub 上的儲存庫。
- **重新命名與移轉**：在 GitHub 重新命名儲存庫或移轉到另一個擁有者，是 GitHub 上的管理操作；本機網址設定可能需要另外更新。
- **操作前確認**：在使用 Push 或 Pull 前，再次檢查遠端網址、分支和儲存庫是否符合預期。

## 實作練習

### 開始之前

請先完成第一階段 [T00](../01-基礎的儲存庫操作-repository-basics/T00-註冊Github與設定VSCode.md)～[T03](../01-基礎的儲存庫操作-repository-basics/T03-推送至遠端Push與從遠端拉取Pull.md)，以及第二階段 [T04](../02-版本控制-version-control/T04-衝突發生的處理.md)～[T08](../02-版本控制-version-control/T08-使用Pull-Request協作.md)，並完成第三階段 [T09](T09-管理儲存庫中的檔案.md) 和 [T10](T10-忽略不需要追蹤的檔案.md)。

在 VS Code 開啟自己有權限操作的測試儲存庫，確認本機與 GitHub 已同步，且 **Source Control**（原始檔控制）的 **Changes**（變更）和 **Staged Changes**（已暫存的變更）沒有未完成的工作。本次會修改本機遠端設定；若不確定儲存庫或遠端網址，請先停止並請老師協助。

### 1. 查看目前的遠端位置

1. 在 VS Code 選擇 **Terminal → New Terminal**（終端機 → 新增終端機），確認終端機位於測試儲存庫。
2. 輸入以下指令：

   ```sh
   git remote -v
   ```

3. 查看輸出中的遠端名稱及網址。通常會看到 `origin`，同一遠端可能列出 Fetch 和 Push 兩行。
4. 在 GitHub 網頁開啟你認為對應的測試儲存庫，核對擁有者和儲存庫名稱是否符合 `origin` 網址。若沒有遠端，或網址指向不認識的位置，先不要 Push；請確認本機儲存庫的來源和使用目的。
5. 把原本 `origin` 的網址暫時複製到安全的筆記位置，稍後用來還原設定。不要把網址貼到公開討論或不相關的檔案中。

### 2. 建立一個測試用的遠端目的地

為了安全練習，這一步會建立一個新的空測試儲存庫，作為暫時的遠端位置；不會變更原本儲存庫的內容。

1. 在 GitHub 建立一個自己擁有的私人測試儲存庫，例如 `remote-target-practice`。先不要加入 README、`.gitignore` 或授權檔，讓它保持空白。
2. 在新儲存庫頁面選擇 **Code**，複製 HTTPS 網址。確認擁有者及儲存庫名稱是剛才建立的測試目的地。
3. 回到 VS Code 終端機，使用以下指令新增一個名為 `practice-target` 的遠端。將 `<測試目的地網址>` 換成剛複製的網址，不要輸入尖括號或佔位文字：

   ```sh
   git remote add practice-target <測試目的地網址>
   ```

4. 再次執行 `git remote -v`，確認清單中同時有原本的 `origin` 和新的 `practice-target`，且網址各自指向預期的儲存庫。

如果新增遠端時顯示名稱已存在，先用 `git remote -v` 查看它目前指向哪裡；不要直接覆蓋不認識的設定。

### 3. 修改並還原遠端網址

我們會暫時把 `origin` 指向剛才的測試目的地，確認修改的是本機連線設定，然後立刻還原。**此步驟不要 Push 或 Pull。**

1. 確認原本 `origin` 網址已妥善記下，且 `practice-target` 指向新建的空測試儲存庫。
2. 輸入以下指令，將本機的 `origin` 改指向測試目的地：

   ```sh
   git remote set-url origin <測試目的地網址>
   ```

3. 執行 `git remote -v`，確認 `origin` 現在指向測試目的地。此時只改變本機設定，GitHub 上原本的儲存庫沒有被移動或修改。
4. 立即用以下指令將 `origin` 還原為步驟 1 記下的原始網址：

   ```sh
   git remote set-url origin <原本origin網址>
   ```

5. 再執行 `git remote -v`，確認 `origin` 已回到原本的測試儲存庫，`practice-target` 仍指向新建的測試目的地。
6. 確認 `practice-target` 是本次建立的測試遠端後，移除本機上的這筆測試設定：

   ```sh
   git remote remove practice-target
   ```

7. 最後執行 `git remote -v`，確認只剩下原本預期的遠端設定，並回到 GitHub 核對 `origin` 所指向的儲存庫。

如果任何一步的網址或遠端名稱和預期不同，先停止，不要 Push 或 Pull。用記下的原始 `origin` 網址還原，若不確定就請老師協助。

### 4. 分清楚修改網址與移轉儲存庫

- **修改遠端網址**：像剛才的 `git remote set-url`，只改本機儲存庫中的連線設定。GitHub 上原本的儲存庫仍留在原位置，其他協作者的設定也不會自動改變。
- **重新命名 GitHub 儲存庫**：在 GitHub 的儲存庫設定中變更名稱。儲存庫仍屬於同一個擁有者，但網址會改變；本機可能要更新遠端網址，協作者也要留意新位置。
- **移轉 GitHub 儲存庫**：在 GitHub 將儲存庫移至另一位使用者或組織。這會改變 GitHub 上的擁有者與管理權限，不是只改本機 `origin`。只有具備相應權限的人才能操作，移轉前應先與新的擁有者確認存取權、協作者和專案設定。

本課只在本機練習修改遠端設定，不實際重新命名或移轉任何 GitHub 儲存庫。若日後需要移轉正式專案，先確認目標擁有者、權限、網址與專案規則，再依 GitHub 的<a href="https://docs.github.com/en/repositories/creating-and-managing-repositories/transferring-a-repository" target="_blank" rel="noopener noreferrer">移轉儲存庫說明</a>操作；不確定時請專案管理者協助。

## 小測驗

在進入下一課之前，來試試看吧！請選出**一個**答案，再展開下方解答確認。

**問題：** 我執行 `git remote set-url origin <新網址>`，這個動作代表什麼？

- A. 將 GitHub 上的儲存庫和所有協作者移轉到新擁有者。
- B. 修改目前本機儲存庫中 `origin` 所指向的網址。
- C. 自動把本機所有提交 Push 到新網址。
- D. 刪除原本 GitHub 儲存庫。

<details>
<summary>查看答案</summary>

答案是 **B**。`git remote set-url` 只會更新本機儲存庫的遠端網址設定，不會搬移、刪除或自動推送 GitHub 上的儲存庫。

</details>
