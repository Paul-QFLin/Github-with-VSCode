# T10：忽略不需要追蹤的檔案

> 所屬階段：[回到第三階段：檔案與 Repo 管理](README.md) · [課程總覽](../../README.md)

## 任務目標

在 T09，我們練習了新增、刪除和重新命名檔案，也學會選擇要提交的變更。這一課，老師會帶你建立 `.gitignore`，告訴 Git 哪些尚未追蹤的檔案通常不需要加入版本控制，例如產生的紀錄檔和本機個人設定。

`.gitignore` 不會刪除檔案，也不會自動停止追蹤已經提交過的檔案。請在自己的測試儲存庫練習，不要把真正的密碼、權杖或其他敏感資料放進任何練習檔案。

## 學習重點

- **`.gitignore`**：放在儲存庫中的規則檔，讓 Git 忽略符合規則且尚未追蹤的檔案。
- **忽略未追蹤檔案**：符合 `.gitignore` 規則的新檔案不會出現在一般待提交清單中；檔案仍留在電腦上。
- **已追蹤檔案不受追溯影響**：檔案若已被 Git 記錄，即使後來加入忽略規則，Git 仍會繼續追蹤它的修改。
- **規則寫法**：可以忽略特定檔名、副檔名或資料夾。請只加入專案確實不需要追蹤的項目，以免忽略了應該分享的檔案。
- **敏感資料**：`.gitignore` 是降低誤提交機會的保護措施，不是秘密資料的安全儲存方式。不要把真正的密碼或權杖寫入練習檔案或 Commit。

## 實作練習

### 開始之前

請先完成第一階段 [T00](../01-基礎的儲存庫操作-repository-basics/T00-註冊Github與設定VSCode.md)～[T03](../01-基礎的儲存庫操作-repository-basics/T03-推送至遠端Push與從遠端拉取Pull.md)，以及第二階段 [T04](../02-版本控制-version-control/T04-衝突發生的處理.md)～[T08](../02-版本控制-version-control/T08-使用Pull-Request協作.md) 和第三階段 [T09：管理儲存庫中的檔案](T09-管理儲存庫中的檔案.md)。

在 VS Code 開啟自己有權限操作的測試儲存庫，確認資料夾與分支正確，並依 T03 確認本機與 GitHub 已同步。檢查 **Source Control**（原始檔控制）的 **Changes**（變更）和 **Staged Changes**（已暫存的變更）；若有未完成的修改，先妥善保留，不要把不相關的內容一起提交或丟棄。

這次會使用 `tracked-practice.log`、`new-practice.log` 和 `local-notes.txt` 作為練習檔名。如果已有同名檔案，請改用新的名稱。請勿在練習檔中填入真實密碼、權杖或個人資料。

### 1. 建立並提交一個已追蹤的練習檔案

1. 在 VS Code 檔案總管新增 `tracked-practice.log`，輸入並儲存：

   ```text
   這是已追蹤檔案的練習內容。
   ```

2. 在 **Source Control** 確認只有這個練習檔案，將它 Stage（暫存），以 `新增已追蹤的練習紀錄檔` 為訊息 Commit。
3. 確認這次 Commit 已完成。這個檔案現在已被 Git 追蹤，稍後即使加入 `*.log` 忽略規則，它的修改仍會被 Git 偵測。

### 2. 建立 `.gitignore` 規則

1. 在 VS Code 檔案總管的儲存庫根目錄新增 `.gitignore`。請確認檔名開頭有一個句點，且不是 `gitignore.txt`。
2. 在檔案中輸入以下規則並儲存：

   ```gitignore
   # 練習用的紀錄檔
   *.log

   # 本機個人備忘，不需分享
   local-notes.txt

   # 本機環境設定檔，可能含敏感資料
   .env
   ```

   `*.log` 會符合所有以 `.log` 結尾的檔案；`local-notes.txt` 和 `.env` 會符合同名檔案（本例將它們放在儲存庫根目錄）。若專案有不同需求，忽略規則可能需要調整。
3. 在 VS Code 新增 `new-practice.log` 和 `local-notes.txt`，分別輸入一般的練習文字並儲存。請勿在 `local-notes.txt` 或 `.env` 中放入真實敏感資料。
4. 回到 **Source Control**：`.gitignore` 應出現在 **Changes**，而新的 `new-practice.log` 和 `local-notes.txt` 不會出現在一般變更清單中。它們仍存在於檔案總管，只是 Git 依規則忽略它們。
5. 確認 **Changes** 中的 `.gitignore` 是本次要提交的練習檔，暫存並以 `新增忽略規則` 為訊息 Commit。

如果 `.gitignore` 也沒有出現在變更清單，先確認檔案是否存到目前儲存庫的根目錄，以及檔名是否正確。不要為了讓新檔案出現而刪除或停用其他設定。

### 3. 確認忽略規則不影響已追蹤檔案

1. 再次開啟 `tracked-practice.log`，在原文後新增一行並儲存：

   ```text
   這行修改仍會被 Git 偵測。
   ```

2. 回到 **Source Control**，確認 `tracked-practice.log` 仍出現在 **Changes**，即使它符合 `.gitignore` 中的 `*.log` 規則。這表示忽略規則不會讓 Git 停止追蹤既有檔案。
3. 點選 `tracked-practice.log` 查看差異，確認只有剛才新增的練習文字。暫存這個檔案，以 `修改已追蹤的練習紀錄檔` 為訊息 Commit。
4. 確認 **Changes** 和 **Staged Changes** 沒有本次練習的未提交內容。檔案總管中的 `new-practice.log` 和 `local-notes.txt` 仍保留在本機，不會因 Commit `.gitignore` 而被刪除。
5. 練習結束後，可以在檔案總管刪除這兩個忽略中的練習檔案；它們尚未被追蹤，刪除時不會成為 Git 變更。保留 `.gitignore` 和 `tracked-practice.log`，可用來查看本次練習結果。

如果曾經把真正的密碼或權杖提交或推送到 GitHub，只新增忽略規則或刪除檔案並不足以保護它；請立即撤銷或更換該憑證，並通知專案管理者處理。

### 終端機補充

在 VS Code 選擇 **Terminal → New Terminal**（終端機 → 新增終端機），確認終端機位於測試儲存庫後，可用以下指令查看一般與忽略中的檔案：

```sh
git status --ignored
```

若想確認某個檔案符合哪一條忽略規則，可以使用：

```sh
git check-ignore new-practice.log
```

執行前請確認檔名和目前的儲存庫。Git 官方文件也有說明 <a href="https://git-scm.com/docs/gitignore" target="_blank" rel="noopener noreferrer">.gitignore 規則</a>。

## 小測驗

在進入下一課之前，來試試看吧！請選出**一個**答案，再展開下方解答確認。

**問題：** `tracked-practice.log` 已經 Commit 過，後來才在 `.gitignore` 加入 `*.log`。修改這個檔案後，Git 會怎麼做？

- A. 忽略檔案的所有修改，因為副檔名符合規則。
- B. 繼續追蹤並顯示它的修改；忽略規則不會自動取消既有追蹤。
- C. 自動刪除這個檔案。
- D. 自動把這個檔案從 Git 歷史中移除。

<details>
<summary>查看答案</summary>

答案是 **B**。`.gitignore` 會忽略符合規則且尚未追蹤的檔案，不會回頭取消已提交檔案的追蹤，也不會刪除檔案。
