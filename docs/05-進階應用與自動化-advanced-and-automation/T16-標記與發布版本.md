# T16：標記與發布版本

> 所屬階段：[回到第五階段：進階應用與自動化](README.md) · [課程總覽](../../README.md)

## 任務目標

在 T14，我們為專案撰寫了 README；在這一課，老師會帶你使用 Git Tag（標籤）標記一個特定版本，再透過 GitHub Release（發布版本）為這個版本撰寫說明。

Tag 指向 Git 歷史中的某個提交，方便辨識特定版本；Release 則是在 GitHub 上為版本提供標題、說明和可選的下載檔案。Tag 不會自動把程式碼打包，建立 Release 也不會自動修改專案檔案。
- **Why or Why Not**: 以Tag標記特定提交並建立Release說明，能清楚識別與傳達發布版本，方便使用者了解版本內容並取得相關檔案。

## 學習重點

- **Tag（標籤）**：指向某個 Commit 的名稱，可用來辨識重要版本。
- **Annotated Tag（附註標籤）**：除了名稱，也記錄標籤訊息和建立者等資訊；本課使用這種標籤。
- **Release（發布版本）**：在 GitHub 上為版本整理標題和發布說明，通常會對應到一個 Tag。
- **Tag 與 Release 的差別**：Tag 是 Git 版本歷史中的標記；Release 是 GitHub 上面向使用者的版本介紹。
- **發布前確認**：確認儲存庫、分支、提交內容和標籤名稱正確，再建立並推送 Tag。

在 GitHub 的儲存庫頁面查看現有 Tags 和 Releases，確認 `v1.0.0` 尚未使用。若已存在，請改用一個新的名稱，並在以下指令及 Release 中一致使用。

### 1. 為目前版本建立 Tag

1. 在 VS Code 開啟 **Terminal → New Terminal**（終端機 → 新增終端機），確認終端機位於 `readme-practice` 儲存庫。
2. 查看目前的分支和最新提交，確認要標記的是已完成且已 Push 的版本：

   ```sh
   git --no-pager log --oneline
   ```

3. 確認目前分支是 `main`，最新提交就是你要發布的版本，而且沒有尚未提交或尚未推送的工作。再輸入以下指令建立附註標籤：

   ```sh
   git tag -a v1.0.0 -m "readme-practice 第一個練習版本"
   ```

   `-a` 代表建立附註標籤，`-m` 後面是標籤說明。若使用不同標籤名稱，請將 `v1.0.0` 一併替換。
4. 輸入以下指令查看標籤指向的提交及標籤訊息：

   ```sh
   git show v1.0.0
   ```

   確認顯示的提交正是步驟 2 要發布的版本。如果標籤指錯提交，先停止操作並請老師協助，不要直接刪除或移動標籤。

### 2. 將 Tag 推送到 GitHub

1. 再次確認目前 `origin` 指向 `readme-practice`，以及標籤名稱和要分享的提交正確。
2. 在終端機輸入以下指令，只推送這個 Tag：

   ```sh
   git push origin v1.0.0
   ```

3. 回到 GitHub 儲存庫頁面，確認 `v1.0.0` 出現在 Tags 清單。Push Tag 不會建立 Release；下一步會在 GitHub 網頁完成發布說明。

如果 Push 被拒絕或出現不熟悉的錯誤，先閱讀訊息並確認遠端和標籤，不要使用 Force Push，也不要重複建立另一個標籤。

### 3. 在 GitHub 建立 Release

1. 在 GitHub 開啟 `readme-practice`，找到 **Releases**，選擇 **Draft a new release**（建立新發布版本）或相近的選項。
2. 在 **Choose a tag**（選擇標籤）中選擇剛才推送的 `v1.0.0`。若找不到，先確認 Tag 已推送到同一個儲存庫，再重新整理頁面。
3. 輸入 Release 標題，例如 `readme-practice v1.0.0`，並撰寫簡短說明，例如：

   ```text
   ## 這個版本包含
   - 新增閱讀清單練習檔。
   - 加入專案用途和使用方式說明。
   ```

4. 再次檢查儲存庫、Tag、標題和說明，確認內容正確後選擇 **Publish release**（發布版本）。這次只發布說明，不需要上傳額外檔案。
5. 回到 Releases 頁面，確認 Release 已出現並連到 `v1.0.0`。也可以選擇 Tag，確認它指向預期的提交。

GitHub 的按鈕或頁面位置可能因版本而不同；如果儲存庫有發布規則，請依專案規定操作。

## 小測驗

在進入下一課之前，來試試看吧！請選出**一個**答案，再展開下方解答確認。

**問題：** 我已經把 `v1.0.0` Tag Push 到 GitHub，這代表什麼？

- A. GitHub 已經自動替專案建立並發布 Release 說明。
- B. 這個 Tag 已上傳並標記一個提交；若要提供版本標題和說明，還要另外建立 Release。
- C. GitHub 已經自動把本機所有未提交修改推送上去。
- D. 原本的 Git 提交紀錄已被 Tag 取代。

<details>
<summary>查看答案</summary>

答案是 **B**。Tag 標記 Git 歷史中的提交；Release 則是在 GitHub 上為 Tag 撰寫版本說明。兩者相關，但不是同一個操作。

</details>
