# T14：撰寫專案說明文件

> 所屬階段：[回到第五階段：進階應用與自動化](README.md) · [課程總覽](../../README.md)

## 任務目標

在前面的課程，我們已經學會管理儲存庫中的檔案。這一課，老師會帶你撰寫專案的 `README.md`，讓第一次看到儲存庫的人知道這個專案是什麼、有哪些內容，以及如何開始使用。

README 通常會顯示在 GitHub 儲存庫首頁。寫好後，我們會用 Markdown（輕量標記語法）整理標題、清單、連結和程式碼，再透過 VS Code 預覽並提交。
- **Why or Why Not**: 清楚的README能讓使用者快速了解專案用途與使用方式，降低開始使用或參與協作的門檻。

## 學習重點

- **README**：專案的介紹文件，常用檔名是 `README.md`，可放在儲存庫根目錄。
- **Markdown**：使用簡單標記整理文字的格式，例如 `#` 標題、`-` 清單、`**粗體**` 和 `[連結文字](檔案路徑)`。
- **專案說明內容**：依專案需要介紹用途、功能、使用方式、檔案位置和相關資源；只描述目前實際存在的內容。
- **預覽與檢查**：在 VS Code 預覽 Markdown，並確認相對連結指向正確檔案。
- **README 與 Git**：README 是一般專案檔案；要分享更新，仍須檢查、Commit 並 Push。

## 實作練習

### 開始之前

請先完成第一階段 [T00](../01-基礎的儲存庫操作-repository-basics/T00-註冊Github與設定VSCode.md)～[T03](../01-基礎的儲存庫操作-repository-basics/T03-推送至遠端Push與從遠端拉取Pull.md)，第二階段 [T04](../02-版本控制-version-control/T04-衝突發生的處理.md)～[T08](../02-版本控制-version-control/T08-使用Pull-Request協作.md)，以及第三、第四階段的 [T09](../03-檔案與儲存庫管理-files-and-repositories/T09-管理儲存庫中的檔案.md)～[T13](../04-多電腦協同工作-multi-computer-workflow/T13-同步VSCode操作環境.md)。

請使用自己的私人測試儲存庫。為了避免覆蓋既有專案說明，建議依 T01 建立一個新的練習儲存庫，例如 `readme-practice`，並加入預設的 `README.md`。在 VS Code Clone 後，確認儲存庫名稱、分支和遠端位置正確，且 **Source Control**（原始檔控制）的 **Changes**（變更）與 **Staged Changes**（已暫存的變更）沒有未完成的工作。

如果想替已有 README 的專案更新說明，請先使用測試儲存庫，檢查並妥善保留原本內容；不要直接覆蓋正式專案的說明文件。

### 1. 新增練習內容檔案

1. 在 VS Code 檔案總管新增 `reading-list.md`，輸入以下內容並儲存：

   ```markdown
   # 閱讀清單

   - Git 入門
   - Markdown 練習
   ```

2. 在 **Source Control** 確認只有 `reading-list.md` 是本次新增的檔案。暫存後以 `新增閱讀清單練習檔` 為訊息 Commit。
3. 依 T03 的方式 Push，並在 GitHub 確認 `reading-list.md` 已出現在測試儲存庫。

這個檔案會成為 README 的連結目標，先確認它已存在，連結才有內容可以開啟。

### 2. 撰寫 README

1. 在 VS Code 開啟儲存庫根目錄的 `README.md`。先確認這是 `readme-practice` 練習儲存庫的 README，再將內容整理成以下範例：

   ```markdown
   # 閱讀清單練習

   這是一個用來練習整理閱讀清單的簡單專案。

   ## 專案用途

   記錄想閱讀的主題，並熟悉使用 GitHub 查看專案說明。

   ## 使用方式

   1. 開啟 [`reading-list.md`](reading-list.md)。
   2. 在清單中新增想閱讀的主題。
   3. 使用 VS Code 的 Source Control 檢查並提交修改。

   ## 專案檔案

   - [`reading-list.md`](reading-list.md)：閱讀主題清單。

   ## Markdown 格式範例

   - 使用 `##` 建立次標題。
   - 使用 `-` 建立項目清單。
   - 使用 `**粗體**` 強調重要內容。
   ```

2. 儲存檔案。README 的說明要符合專案實際內容；在自己的專案中，請替換範例標題、用途和功能，不要保留不適用的描述。
3. 使用 VS Code 預覽 Markdown：在編輯器中按右鍵選擇 **Open Preview**（開啟預覽），或使用預覽按鈕。檢查標題層級、清單、粗體和連結是否正常呈現。
4. 點選預覽中的 `reading-list.md` 連結，確認它能開啟剛才建立的檔案。若連結失效，檢查檔名、大小寫和相對路徑。

VS Code 的預覽選項可能因版本或語言而不同；如果找不到，可以在命令面板搜尋 Markdown Preview。

### 3. 檢查並分享 README

1. 回到 **Source Control**，點選 `README.md` 檢查差異，確認只包含預期的專案說明。
2. 將 `README.md` 暫存，確認 **Staged Changes** 中只有這次的 README 修改，再以 `撰寫專案說明文件` 為訊息 Commit。
3. Commit 完成後依 T03 Push。回到 GitHub 儲存庫首頁，確認 README 已呈現標題、說明、清單和可用的檔案連結。
4. 如果 GitHub 顯示的內容和 VS Code 預覽不同，先確認 Push 成功、目前分支正確，並重新整理 GitHub 頁面。

如果 README 原本包含重要說明，請先檢查差異並保留仍適用的段落；不要為了符合範例而刪掉仍然有效的資訊。

### 常用 Markdown 寫法

| 想呈現的內容 | Markdown 寫法 |
| --- | --- |
| 大標題 | `# 專案名稱` |
| 次標題 | `## 使用方式` |
| 項目清單 | `- 第一項` |
| 編號步驟 | `1. 第一步` |
| 粗體 | `**重要內容**` |
| 程式或檔名 | `` `README.md` `` |
| 連結 | `[閱讀清單](reading-list.md)` |

GitHub 也提供<a href="https://docs.github.com/en/get-started/writing-on-github/getting-started-with-writing-and-formatting-on-github/basic-writing-and-formatting-syntax" target="_blank" rel="noopener noreferrer">Markdown 基本格式說明</a>，可以在需要時查閱。

- A. 確認 `reading-list.md` 存在，並檢查檔名和相對路徑是否正確。
- B. 將 README 改成 `.txt` 檔案。
- C. 使用 Force Push 重新上傳整個儲存庫。
- D. 刪除 GitHub 上的 README，再重新建立另一個儲存庫。
