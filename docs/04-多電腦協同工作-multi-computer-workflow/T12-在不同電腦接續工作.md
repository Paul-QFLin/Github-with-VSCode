# T12：在不同電腦接續工作

> 所屬階段：[回到第四階段：多電腦協同工作](README.md) · [課程總覽](../../README.md)

## 任務目標

在 T03，我們練習了 Push 和 Pull；在 T07、T08，我們也認識了分支和 Pull Request。這一課，老師會帶你使用 GitHub 作為共同的遠端儲存庫，先在一台電腦提交並 Push，再到另一台電腦 Clone 或 Pull，接著把新修改 Push 回 GitHub，最後回到第一台電腦取得更新。

每台電腦都有自己的本機儲存庫，檔案不會因為使用同一個 GitHub 帳號就自動更新。工作告一段落時，先 Commit 並 Push；換電腦後，再確認儲存庫和分支並 Pull，這樣才能安全接續。

## 學習重點

- **不同電腦上的本機儲存庫**：每台電腦的工作目錄和 Git 歷史是各自獨立的。
- **Clone**：第一次在另一台電腦工作時，將 GitHub 上的儲存庫複製到該電腦。
- **Push 與 Pull**：在目前電腦 Commit 後 Push 到 GitHub；換到另一台電腦後 Pull 遠端更新。
- **依序工作**：換電腦前確認已 Commit、Push；開始工作前確認 Pull 完成且工作目錄沒有未完成修改。
- **衝突**：若兩台電腦都各自修改並提交，整合時可能發生衝突；依照 [T04：衝突發生的處理](../02-版本控制-version-control/T04-衝突發生的處理.md) 確認和處理，不要直接丟棄修改或強制推送。

## 實作練習

### 開始之前

請先完成第一階段 [T00](../01-基礎的儲存庫操作-repository-basics/T00-註冊Github與設定VSCode.md)～[T03](../01-基礎的儲存庫操作-repository-basics/T03-推送至遠端Push與從遠端拉取Pull.md)，以及第二階段 [T04](../02-版本控制-version-control/T04-衝突發生的處理.md)～[T08](../02-版本控制-version-control/T08-使用Pull-Request協作.md) 和第三階段 [T09](../03-檔案與儲存庫管理-files-and-repositories/T09-管理儲存庫中的檔案.md)～[T11](../03-檔案與儲存庫管理-files-and-repositories/T11-管理遠端位置與移轉專案.md)。

準備一個自己有寫入權限的私人測試儲存庫，並確認兩台電腦都安裝 Git 和 VS Code，可以登入有權限存取該儲存庫的 GitHub 帳號。若只有一台電腦，可以在不同資料夾 Clone 同一個測試儲存庫，模擬兩台電腦；請勿直接複製整個專案資料夾來代替 Clone。

這次會使用 `multi-device-practice.md`。開始前確認這個檔名沒有被其他檔案使用。本課會依序在一台電腦完成並 Push，再換到另一台電腦工作；請勿兩邊同時修改同一個檔案。

### 1. 在第一台電腦建立並上傳共同版本

1. 在第一台電腦的 VS Code 開啟測試儲存庫，確認資料夾、分支和 GitHub 遠端正確，且 **Source Control**（原始檔控制）的 **Changes**（變更）與 **Staged Changes**（已暫存的變更）沒有未完成的工作。
2. 確認目前分支是 `main`。若儲存庫的 `main` 受保護或不允許直接 Push，請停止並依該專案的 Pull Request 規則操作；本練習請使用自己可直接推送的測試儲存庫。
3. 在檔案總管新增 `multi-device-practice.md`，輸入並儲存：

   ```text
   這是跨電腦接續工作的練習。
   ```

4. 在 **Source Control** 檢查變更，確認只有這個練習檔案。將它 Stage，以 `建立跨電腦練習起點` 為訊息 Commit。
5. 確認提交已完成，再選擇 **... → Push**（更多動作 → 推送）。回到 GitHub 網頁確認檔案和提交已出現。

如果 Push 被拒絕，先閱讀提示並確認遠端更新；不要使用 Force Push（強制推送）。完成這一步前，先不要切換到第二台電腦開始修改。

### 2. 在第二台電腦 Clone 或更新儲存庫

如果第二台電腦**還沒有**這個儲存庫：

1. 在第一台電腦的 GitHub 儲存庫頁面選擇 **Code**，複製 HTTPS 網址。
2. 到第二台電腦開啟 VS Code，執行 **Git: Clone**，貼上剛才複製的網址，並選擇存放測試專案的資料夾。
3. Clone 完成後開啟新複製的儲存庫，確認儲存庫名稱、GitHub 帳號及目前分支正確。

如果第二台電腦**已經 Clone 過**這個儲存庫：

1. 在 VS Code 開啟原本的 Clone 資料夾，確認儲存庫名稱和遠端位置正確。
2. 檢查 **Changes** 和 **Staged Changes**。若有未完成的修改，先妥善保留或完成 Commit；不要在工作未保存時直接 Pull。
3. 確認目前位於 `main` 且工作目錄乾淨，先選擇 **... → Fetch**（擷取遠端更新資訊）。Fetch 只更新本機對遠端版本的認識，不會直接改動工作目錄的檔案。
4. 再選擇 **... → Pull**，取得並整合遠端的提交。

接著在第二台電腦開啟 `multi-device-practice.md`，確認已看到第一台電腦提交的練習起點。如果看不到，先確認 Clone 的網址、目前分支和 Pull 是否成功，不要重複建立同名檔案。

### 3. 在第二台電腦接續修改並上傳

1. 確認仍在第二台電腦的測試儲存庫與 `main` 分支。在 `multi-device-practice.md` 原文後新增一行：

   ```text
   這一行是在另一台電腦接續完成的。
   ```

2. 儲存檔案，在 **Source Control** 查看差異，確認只有新增的練習文字。將修改暫存，以 `從另一台電腦接續工作` 為訊息 Commit。
3. 確認提交完成後選擇 **... → Push**。回到 GitHub 確認新增文字和提交訊息已出現。

Push 完成後，先不要回第一台電腦修改同一份檔案；下一步要先把遠端更新 Pull 回去。

### 4. 回到第一台電腦取得更新

1. 回到第一台電腦，開啟原本的測試儲存庫，確認資料夾和分支正確。
2. 在 **Source Control** 確認沒有未提交或未暫存的修改。若有其他工作，先妥善保留，不要直接丟棄。
3. 確認目前位於 `main`，選擇 **... → Pull**，取得第二台電腦剛才 Push 的提交。
4. 開啟 `multi-device-practice.md`，確認第一台電腦的起點和第二台電腦新增的文字都在本機。

完成後，兩台電腦都已透過 GitHub 取得最新版本。GitHub 是兩邊交換提交的遠端位置；它不會自動同步尚未 Commit 的修改。

### 換電腦前後的小提醒

- **離開目前電腦前**：儲存、檢查變更、Commit，再 Push；確認 GitHub 上已看得到提交。
- **開始另一台電腦的工作前**：確認開啟的是正確儲存庫和分支，先 Pull，並確認沒有未完成的本機修改。
- **管理多個專案時**：在 VS Code 開啟或切換資料夾後，先看檔案總管、分支名稱和遠端位置，再開始修改；不要只依視窗標題猜測目前專案。
- **發生衝突時**：先保留工作並閱讀提示，依 T04 比較修改並完成整合；不要用 Force Push 覆蓋遠端內容。

## 小測驗

在進入下一課之前，來試試看吧！請選出**一個**答案，再展開下方解答確認。

**問題：** 我在第一台電腦完成修改並 Push，準備到第二台電腦接續工作。第二台電腦應該先做什麼？

- A. 在第二台電腦建立另一個同名儲存庫，直接開始修改。
- B. 確認是正確的儲存庫和分支，檢查並妥善保留未完成修改，再 Pull 最新版本。
- C. 直接 Force Push，讓 GitHub 覆蓋第二台電腦的檔案。
- D. 把第一台電腦的專案資料夾用檔案總管複製過去，不必使用 Git。

<details>
<summary>查看答案</summary>

答案是 **B**。先確認儲存庫與分支，並保留第二台電腦可能已有的工作，再 Pull 取得遠端更新。第一次在第二台電腦工作時，應 Clone 儲存庫，而不是手動複製專案資料夾。
