# T13：同步 VS Code 操作環境

> 所屬階段：[回到第四階段：多電腦協同工作](README.md) · [課程總覽](../../README.md)

## 任務目標

在 T12，我們用 GitHub 和 Git 在不同電腦之間接續專案工作。這一課，老師會帶你認識 VS Code 的 Settings Sync（設定同步），將選定的編輯器設定同步到另一台電腦，例如使用者設定、鍵盤快捷鍵、程式碼片段和擴充功能。

Settings Sync 同步的是 VS Code 的個人操作環境，不是專案檔案；專案內容仍要使用 Git 的 Commit、Push 和 Pull。同步前先選擇想分享的項目，並確認登入的是自己的帳號，避免把不適合其他電腦使用的設定套用過去。
- **Why or Why Not**: 同步選定的VS Code設定能讓不同電腦維持熟悉的操作環境；理解它與Git同步專案檔案的差異，可避免誤以為程式碼也會隨設定同步。

## 學習重點

- **Settings Sync**：VS Code 提供的設定同步功能，使用登入的 GitHub 或 Microsoft 帳號同步選定的個人設定。
- **可同步的項目**：可以選擇設定、鍵盤快捷鍵、使用者程式碼片段、擴充功能及其他 VS Code 支援的設定類別；實際選項可能因版本而異。
- **專案檔案與設定的差別**：程式碼和文件要透過 Git 同步；個人 VS Code 設定可透過 Settings Sync 同步。
- **同步前先檢查**：不同電腦可能有各自的設定。若畫面詢問如何處理本機與雲端設定，先閱讀選項，避免未確認就覆蓋本機設定。
- **依電腦調整**：某些擴充功能或設定只適合特定作業系統或電腦；可選擇不同步這些項目，或依需要在各電腦調整。

## 實作練習

### 開始之前

請先完成第一階段 [T00](../01-基礎的儲存庫操作-repository-basics/T00-註冊Github與設定VSCode.md)～[T03](../01-基礎的儲存庫操作-repository-basics/T03-推送至遠端Push與從遠端拉取Pull.md)，第二階段 [T04](../02-版本控制-version-control/T04-衝突發生的處理.md)～[T08](../02-版本控制-version-control/T08-使用Pull-Request協作.md)，第三階段 [T09](../03-檔案與儲存庫管理-files-and-repositories/T09-管理儲存庫中的檔案.md)～[T11](../03-檔案與儲存庫管理-files-and-repositories/T11-管理遠端位置與移轉專案.md)，以及第四階段 [T12：在不同電腦接續工作](T12-在不同電腦接續工作.md)。

準備兩台自己有權限使用的電腦，並在兩台電腦都安裝 VS Code。若只想先熟悉功能，也可以先在目前電腦檢查 Settings Sync 的狀態，等有第二台電腦時再驗證同步結果。請不要在公用或他人共用的電腦啟用個人設定同步。

### 1. 在第一台電腦選擇要同步的設定

1. 在第一台電腦開啟 VS Code，查看左下角或活動列中的 **Accounts**（帳戶）選單，確認登入的是自己的 GitHub 或 Microsoft 帳號。
2. 從 **Accounts** 選單找到 **Backup and Sync Settings**（備份與同步設定）或相近的設定同步選項；不同 VS Code 版本可能會在選單或命令面板中顯示。
3. 選擇開啟 Settings Sync。若尚未登入，依提示登入並確認帳號正確。
4. 在同步項目清單中選擇想同步的內容，例如 **Settings**（設定）、**Keyboard Shortcuts**（鍵盤快捷鍵）、**User Snippets**（使用者程式碼片段）或 **Extensions**（擴充功能）。若某項設定只適合這台電腦，可以先不要選取。
5. 確認選取項目後啟用同步。回到帳戶選單，確認 Settings Sync 已開啟；介面名稱和位置可能因版本而異。

如果 VS Code 詢問要如何處理既有的本機或雲端設定，先閱讀畫面說明。若兩邊都有要保留的設定，選擇合併選項；若選擇以雲端設定取代本機設定，可能會覆蓋這台電腦原有的操作環境，不確定時先取消並請老師協助。

### 2. 在第二台電腦登入並同步

1. 在第二台電腦開啟 VS Code，透過 **Accounts** 選單登入與第一台電腦相同的帳號。
2. 找到 Settings Sync 選項並開啟。若 VS Code 提供同步項目選擇，確認這些項目適合第二台電腦後再繼續。
3. 等待同步完成。若畫面詢問要合併或取代本機設定，先檢查目前電腦是否有需要保留的設定，再依需要選擇；不確定時先取消。
4. 查看 VS Code 的設定、鍵盤快捷鍵、程式碼片段或擴充功能，確認所選項目已同步。擴充功能可能需要時間下載或重新載入。
5. 若某些設定不適合第二台電腦，可以在第二台電腦調整，或在 Settings Sync 項目中取消該類別的同步。

如果沒有看到設定更新，先確認兩台電腦登入的是同一個帳號、Settings Sync 已啟用，並查看 VS Code 顯示的同步狀態；不要反覆切換帳號或選擇覆蓋。

### 3. 分清楚設定同步與專案同步

1. 在第二台電腦開啟 T12 練習的 Git 儲存庫。即使 Settings Sync 已開啟，專案檔案也不會因此自動出現在這台電腦。
2. 依 T12 的方式 Clone 儲存庫，或在已 Clone 的工作目錄中 Pull，確認專案檔案已由 Git 取得。
3. 記住這兩種同步的用途：

   - **Settings Sync**：同步選定的 VS Code 個人操作環境。
   - **Git／GitHub**：透過 Commit、Push 和 Pull 管理及分享專案檔案與版本。

   專案自己的 `.vscode` 設定檔若要與協作者共享，應先檢查內容是否適合放進專案，再依專案規則透過 Git 提交；不要把個人或敏感設定意外提交。

### 4. 在共用電腦停止同步

如果你曾在不再使用的電腦登入並啟用 Settings Sync，先到 VS Code 的 **Accounts** 或設定同步選單查看同步狀態，依畫面選擇關閉同步或登出帳號。完成後確認該電腦不再使用你的個人 VS Code 帳號；不要只刪除專案資料夾，因為這不會關閉設定同步。

VS Code 的功能名稱或操作位置可能隨版本更新；可參考官方的 <a href="https://code.visualstudio.com/docs/configure/settings-sync" target="_blank" rel="noopener noreferrer">Settings Sync 說明</a>。

## 小測驗

在進入下一課之前，來試試看吧！請選出**一個**答案，再展開下方解答確認。

**問題：** 我在第一台電腦啟用了 VS Code Settings Sync，換到第二台電腦後，專案的程式碼會自動出現嗎？

- A. 會，Settings Sync 會同步整個 GitHub 專案。
- B. 不會；Settings Sync 同步選定的 VS Code 操作環境，專案檔案仍要用 Git Clone 或 Pull。
- C. 會，但只有在第二台電腦使用相同鍵盤時才會同步。
- D. 不會；程式碼只能用電子郵件寄到第二台電腦。

答案是 **B**。Settings Sync 和 Git 的用途不同：前者同步選定的 VS Code 設定，後者透過 GitHub 管理專案檔案和版本。
